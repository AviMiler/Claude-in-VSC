## Models: mandatory
**Development of this project MUST use only the models below, by the task type below. Fable is NOT used here; Opus is the strongest model allowed.**

| Task | Model (mandatory) |
|---|---|
| Packages A, C, E, G (settings, shortcuts, `/` menu, error cards, accessibility), and package B's sessions/history/rename | **Sonnet 5.5** (`claude-sonnet-5-5`) |
| Package B's checkpoints, background tasks, `/diff`, `/loop`; package D's model-switch restart with `--resume`; package F (IDE server and its hand-written WebSocket codec, per-block diff approval); any change to the stream-json/control protocol handling or to permission handling; code review between packages | **Opus 5.5** (`claude-opus-5-5`) |
| Trivial edits only (doc wording, renames, small fixes) | **Haiku 5.5** (`claude-haiku-5-5`) |

If the session is not on the required model for the task, **stop and ask the user to switch** before writing code.

## Subagent and session limits: mandatory
Added 2026-11-05 after a single Opus subagent used about 4.1M effective tokens on one small change (F-8/F-9; 25% of it was two cache rewrites after idle gaps, 15% was hunting for Node and building ad-hoc test harnesses).
- **No environment hunting.** If `node` is missing or a check cannot run, STOP and report what could not run and the exact command for the user. Do not search the disk for runtimes, do not build a fake server, a harness page or a compiled helper to stand in for the test run.
- **Install nothing** (no winget/choco/npm/pip, no downloads, no services) without asking the user first.
- **Budget in the brief.** Every subagent/session brief states a call limit (default 40 tool calls for a small fix) and says: at the limit, commit what is done and report; do not continue.
- **Small reads.** Read line ranges, not whole files (`sed -n`, Grep with context); never dump a changelog or a whole transcript. Load only the skills the stage needs.
- **No waiting.** A background agent must finish and report in its final message; it must not wait on timers, servers or browser pages (idle gaps expire the prompt cache: a subagent's cache survived under 10 minutes, so each wake-up rewrites its whole context).
- **Split big work** into separate short agents (build, then docs) instead of one long agent whose context grows past 200k tokens.

## What this is
A VS Code extension (plain JS, no build, no npm) that is a Hebrew RTL front for the real `claude` CLI. The CLI is the only source of truth: the extension persists nothing (no globalState/workspaceState/own files) and reads history read-only from `~/.claude/projects/<encoded cwd>/*.jsonl`.

## Environment constraint: no internet (mandatory)
The user's machine has **no internet access**. Every plan, design and dependency must respect this:
- **Files can be brought in, in small amounts.** The user can copy a few files onto the machine (delivered as described under "Working agreements" below).
- **No installs from the network:** no `npm install`, no marketplace or extension downloads, no package managers, no fetching at runtime. Anything that needs the network to install or update is ruled out.
- **Code libraries only as a last resort:** vendor a library (plain files under `webview/vendor/` or similar) only in special cases where there is truly no other way. First try the platform (VS Code APIs, Node built-ins, the CLI) and hand-written code. Record every such exception in `DEPENDENCIES.md` with the reason no alternative exists.
- When proposing a feature, say what it needs from outside the repo; if it needs an install or a library, say so before anything else.

## How to work here
- Tests: PowerShell, `node --test "test/*.test.js"` (Node 22 needs the glob). Node is not on the Bash PATH.
- Run: `code --extensionDevelopmentPath=<repo>`; `claudeLocal.claudePath` can point to `dev/fake-claude.cmd`. Browser UI preview: `.claude/launch.json` "chat-preview".
- Do not add persistence or a build step; do not write to the CLI's transcripts. Docs are English; every user-facing string and every question to the user is Hebrew.
- Working agreements with the user:
  - Decisions are asked one at a time with all implications (cost, pros, cons). When the user only asks a question, change no files.
  - Findings and changes go into the matching document, not only into the chat. Project docs are English; the exceptions that address the user are Hebrew (`SETUP.md`).
  - The user's machine has no GitHub access: anything meant to run there is delivered as a self-contained file (a .txt saved as UTF-8 with BOM and CRLF opens correctly in Notepad), and results come back as pasted text or screenshots.
  - Checks against the real CLI and model are run by the user from commands prepared here; scripts are tested first against `dev/fake-claude.js`. See `dev/README.md`.
