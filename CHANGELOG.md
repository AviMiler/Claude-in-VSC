# Changelog

Newest first. Each entry: what changed + why. Dates are commit dates.

## 2026-11-01
- **Docs reorganised** (no extension code touched): removed the old `plan.md`, `git-instructions.md` (merged into `AGENT_CONTEXT.md`) and the one-time probe guides `docs/cli-checks*`, `docs/remaining-checks-*.txt`, `docs/gateway-probe-guide.txt` (their scripts are the same files as `dev/probe*.js`; how to run them is now `dev/README.md`); rewrote `spec.md` as a single "as built" document with one "Verification status" section; rewrote `SETUP.md` as one install guide with one merged `env` block; rewrote `docs/litellm-gateway.md` as a current-state reference; removed the overlapping sections from `docs/conclusions.md`; shortened `AGENT_CONTEXT.md` to the current state. Why: only the needed files should remain, each with all of its relevant content in one place.
- **`package.json`: Ctrl+Alt+C added** as a second key for `claude-local.editor.open`. Why: Ctrl+Shift+Esc is Windows' Task Manager shortcut and does not reach VS Code.
- **Final plan and conclusions** (`docs/final-plan.md`, `docs/conclusions.md`): every roadmap decision (stages 1-8 and the six final ones) with its reason and source, the settings table with types and defaults, the build order (packages A-G), and every conclusion with its evidence plus what is still unknown. Two adjustments of mine await the user's approval: cost removed from the usage line, and no model switch during an active turn.
- **Six open decisions closed by the user** (`DECISIONS.md`): model list from the gateway (`GET /v1/models`); no `!` mode; auto permission mode with a warning; model switch by restarting the process with `--model`, the three `ANTHROPIC_DEFAULT_*_MODEL` variables and `--resume`; `claudePath` = `claude-bin.exe` with the extension supplying `API_TIMEOUT_MS`, `CLAUDE_ENABLE_STREAM_WATCHDOG` and `CLAUDE_CODE_MAX_CONTEXT_TOKENS`; model filtering by auto-hiding JSON-title models plus `claudeLocal.modelDenylist`. New settings planned: `gatewayUrl`, `environmentVariables`, `modelDenylist`. Why: the `claude.cmd` wrapper asks for a model number before every run, the CLI does not know the local model's window, and capability flags in the gateway are unreliable.
- **Gateway and Ollama measured** (`docs/litellm-gateway.md`, `dev/gateway-probe/`): the extension host reaches the LiteLLM gateway; `/v1/models` needs no key; the gateway's `num_ctx` is not enforced (prompt grows linearly to 50,012 tokens, `/api/ps` shows 64,000); a cold model load takes 285 s; two models are forced to JSON-title output; effort is fixed to `high`. Why: to know what the model picker, the context meter and the timeouts can rely on.
- **CLI probed on the user's machine** (CLI 2.1.246, VS Code 1.91.1, `qwen3.8:27b`) with `dev/probe-standalone.js`, `probe2-standalone.js`, `probe3-standalone.js`: interrupt, resume/fork, queued messages, MCP control requests, `get_context_usage`, background tasks, `/loop`, vision, rewind (needs `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=1` and `--replay-user-messages`), `updatedInput` on Edit, auto mode, `--model` at launch all work; there is no thinking, no `TodoWrite`, and `set_model` never validates. In plan mode the plan arrives as assistant text and `ExitPlanMode` has an empty `input`; the plan-approval buttons do not appear in VS Code (checked last). Why: the roadmap should not rest on assumptions. Details: `docs/conclusions.md`.
- **`SETUP.md`**: `claudeLocal.claudePath` must be `claude-bin.exe`; the `engines.vscode` note aligned to `^1.91.0`. The extension runs and answers in VS Code 1.91.1 (user report).
