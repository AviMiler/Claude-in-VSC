# Git instructions

- Work on `develop`. One commit per finished task (code + its docs + any spec change together), straight on `develop`.
- No remote yet: do not push. When a GitHub remote is added, ask the user before the first push.
- Stage only the files the task touched; never `git add -A`.
- Never force-push, never skip hooks. `master` gets `develop` only when the user decides a version is ready.
