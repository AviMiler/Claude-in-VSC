# Spec — Claude Code Local (VS Code extension), as built

What the extension is and does today (the "basic version", v0.1.0). User decisions are recorded in `DECISIONS.md`; the roadmap for what comes next, with the reason for each decision, is `PLAN.md`; findings about the CLI and the environment are in `DEPENDENCIES.md`; the setup is in `SETUP.md`. Verification status of everything below: last section.

## Purpose & principles
- A VS Code extension that looks and behaves as close as possible to the official Claude Code extension: send a question, get the answer, render all formatting (Markdown, code with highlighting, thinking, tool rows). Basics only: conversation history of the open folder, the CLI's skills/commands, permissions, model and mode.
- **The CLI is the only source of truth. The extension is a front, not a store.** It holds no data of its own: no `globalState`, no `workspaceState`, no files it writes, no archive, groups, unread flags, local renames, or reload-restore state (user decision). Everything shown is either live from the running CLI process or read read-only from the CLI's own transcript files. In-memory state that dies with the window (open conversations and their replay logs, the pending permission cards, unread/running markers, the closed list) is allowed; persisting it is not.
- The extension never talks to a model; the CLI does. The CLI decides about permissions; the extension only relays.
- Design matters: the UI mirrors the official extension's layout and visual language (see "Chat webview").

## Platform constraints
- A small extension of its own; nothing is copied from the older OneDrive project (user decision).
- Runs on Windows with VS Code and the real `claude` CLI installed (development also uses Node 22). Must eventually run on an offline machine: no CDNs or remote fonts from the webviews and no network access from the webviews. The extension host makes one exception (built in package D): a read-only `GET /v1/models` and `GET /v1/model/info` to the user's own model gateway, in memory only (`DECISIONS.md`, 2026-11-01).
- Language: plain JavaScript only. CommonJS (`require`) in the extension host, plain `<script>` files in the webview. No TypeScript, no `npm install`, no build step, no bundler.
- The only third-party code allowed is vendored, plain-JS, self-running files saved in the repo at a pinned version with their license files: `marked` (Markdown to HTML) and `highlight.js` (common-languages bundle) under `webview/vendor/` (`DEPENDENCIES.md`). Everything else is hand-written.
- `engines.vscode`: `^1.91.0` (VS Code 1.91.1 on the user's machine did not load the extension with the original `^1.94.0`). The secondary-sidebar container is used from 1.106 (the official extension's threshold, `src/util/vscode-version.js`); older versions fall back to the activity bar (see "Placement").
- The CLI is not bundled. It comes from `claudeLocal.claudePath` (default `claude`; on the user's machine the real `claude-bin.exe`, see `SETUP.md`). Target CLI: 2.1.181 or newer (built against 2.1.181; the user's machine runs 2.1.246). A bare name is resolved on PATH by scanning PATH x PATHEXT; a `.cmd`/`.bat` is run through `cmd.exe /d /s /c`.
- `capabilities.untrustedWorkspaces.supported: false`: the extension does not run in Restricted Mode.
- Ids are renamed so the extension installs side by side with the official one: commands `claude-local.*`, settings `claudeLocal.*`, views `claudeLocal*`, view containers `claude-local-*`, context keys `claude-local.*`.
- Code is separated by feature: a folder per topic under `src/` and `webview/`, no cross-feature spaghetti.
- Known limit: Ctrl+Shift+Esc is Windows' Task Manager shortcut, so it will probably never reach VS Code; kept as specified. Ctrl+Alt+C is a second binding for the same command (it works on Windows). The editor/title button, the status-bar item and the command palette are the working entry points. Ctrl+Esc (`claude-local.focusToggle`) normally opens the Windows Start menu; it is kept as decided and its conflict is an unverified user item (`SETUP.md` section 7: if the Start menu opens, rebind the command via "Claude Code Local: Keyboard Shortcuts").
- All VS Code-level shortcuts are `contributes.keybindings`, so they are rebindable in VS Code's shortcut editor; the command "Claude Code Local: Keyboard Shortcuts" opens `workbench.action.openGlobalKeybindings` filtered to `claude-local`. Shortcuts inside the chat webview are separate: the `claudeLocal.keybindings.*` settings (see "Chat webview").
- Code: `package.json`, `extension.js`, `.vscodeignore`, `src/util/vscode-version.js`.

## Placement
One place, one rule (user decision 2026-11-02, `DECISIONS.md`). A single **place** hosts several conversations, one visible at a time, each with its own CLI process. The rule lives in `src/panels/places.js` (`places.main()`).
- **Default place: the sidebar view** (`claudeLocal.preferredLocation` = `sidebar`). The alternative is **one** editor tab (`panel`): a `WebviewPanel`, viewType `claudeLocalPanel`, icon the mascot, title "Claude" (the active conversation's title with a marker, see below). An existing place is focused, never duplicated: there is never a second tab. With `claudeLocal.lockEditorGroups` the tab's group is locked after creation.
- **Main button** (`claude-local.open`: the editor/title button, the status-bar item, Ctrl+Alt+C, Ctrl+Shift+Esc): reveals/focuses the place named by `preferredLocation` and, with `claudeLocal.useTerminal`, opens the CLI in a terminal instead. The URI handler uses the same `places.main()`.
- **Sidebar view:** `claudeLocalSidebarSecondary` in the `secondarySidebar` container `claude-local-sidebar-secondary` (shown when `!claude-local:doesNotSupportSecondarySidebar`), and `claudeLocalSidebar` in the `activitybar` container `claude-local-sidebar` (shown when `claude-local:doesNotSupportSecondarySidebar`, the fallback for old VS Code). At activation the extension sets that context key from `vscode.version`. Both views are `type: webview`. The `ConversationHost` outlives the `WebviewView`: when the view is disposed or hidden the conversations and their processes keep living.
- **Several conversations in one place.** `src/panels/conversation-host.js` holds the open `Conversation`s of the place; exactly one is attached to the webview. "New conversation" while another runs (or waits for a permission) creates a new conversation and shows it; the other **keeps running in the background** (its CLI process is not interrupted). The webview is re-drawn from in-memory state on every switch (`src/panels/replay-log.js` records what a hidden conversation would have shown, folding streamed deltas per block; the `restore` message redraws it in one pass). A permission request or question that arrives while hidden stays pending and is signalled; a turn that ends while hidden marks the conversation unread. Nothing is persisted. Root cause fixed here: `Conversation.newConversation()` used to return early when `busy` (F-2); `newConversation`, `openSession`, `listHistory` and `openInNewTab` no longer exist on `Conversation`.
- **Signals for hidden conversations (in memory only):** status dots in the drawer (running = orange pulsing, waiting for permission = blue, finished unread = orange); in the sidebar `view.badge` = number of hidden waiting + unread conversations and the view description = the title; in the editor tab the title prefix blue circle (waiting) / orange circle (finished unseen).
- Commands (palette titles keep the English "Claude Code Local:" prefix plus a Hebrew title; every webview string is Hebrew). Removed in Fix 1: `editor.open`, `editor.openLast`, `sidebar.open`, `history.open`, `history.refresh`, `history.filter`, `history.rename`.

  **Logging.** Every line is `HH:MM:SS.mmm [WARN|ERROR] [tag] text`; tags are fixed per feature (`src/util/log-tags.js`: spawn, stream, permission, queue, history, session, mcp, uri, error-card, model-switch, context, checkpoint, diff, tasks, background, display, settings, control, general). Setting `claudeLocal.logLevel`: `info` (default) or `debug` (adds a type/size summary of every stream line). The log never contains message text, file contents, tokens or environment values (counts, names, ids, lengths only; `redact` also masks `sk-…`, Bearer tokens and `*KEY/TOKEN/SECRET/PASSWORD=` pairs). Webview events go through the `log` message (allowed tags only) to the same logger.

  `claude-local.newConversation` is also bound to Ctrl+N, only when `claudeLocal.enableNewConversationShortcut` is on and the focus is in the chat (`when`: `activeWebviewPanelId == 'claudeLocalPanel' || focusedView =~ /^claudeLocalSidebar/`), so VS Code's "New File" is not overridden elsewhere.

- Status bar: a right-side item "✻ Claude" running `claude-local.open`; works without an open file.
- Tab title markers (in memory only; VS Code has no tab colour API, so an emoji prefix is added to the editor-tab title; the sidebar uses `view.badge`): see "Signals for hidden conversations" above.
- Lifetime: closing a conversation (the drawer's close button, which asks "לסגור?" while a turn runs) kills its process and puts it on the in-memory closed list. Disposing the sidebar view or closing the editor tab does **not** kill anything (the host outlives the webview); all processes die when the extension deactivates. Nothing is remembered: after a window reload nothing is restored (no `WebviewPanelSerializer`), and conversations are reachable again through the drawer's past conversations.
- Code: `src/panels/` (`places.js`, `conversation-host.js`, `replay-log.js`, `chat-panel.js`, `sidebar-view.js`, `panel-registry.js` (in-memory only), `commands.js`, `status-bar.js`, `index.js`), `src/cli/terminal.js` (Open in Terminal), `src/util/workspace.js` (`workspaceCwd`, shared by the chat and the terminal), `package.json` `contributes`.

## Process & protocol
One long-lived CLI process per conversation, spoken to over stdin/stdout with stream-json and the control protocol (user decision).
- Spawn: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio --permission-mode <mode>`, plus `--resume <sessionId>` to continue a past conversation and `--model <m>` when the user picked one. No capability probing: the target CLI is fixed (2.1.181+), an unknown-flag failure is reported in Hebrew. Package H adds `--mcp-config <inline JSON>` and `--allowedTools mcp__claude-local-nav` for the extension's own navigation server (no `--strict-mcp-config`, so the user's other MCP servers still load); if that server fails to start, the CLI is spawned without them (see "Code navigation MCP server").
- `cwd`: the first workspace folder. No folder open: the user's home folder, and the composer shows "לא נפתחה תיקייה – Claude עובד בתיקיית הבית".
- Environment: `process.env`, then `claudeLocal.environmentVariables` merged over it (default `API_TIMEOUT_MS=1200000`, `CLAUDE_ENABLE_STREAM_WATCHDOG=0`, `CLAUDE_CODE_MAX_CONTEXT_TOKENS=64000`; values coerced to strings, invalid entries ignored; applies from the next process start), then `CLAUDE_CODE_ENTRYPOINT=claude-local-vscode`. The same merged environment is used by Open in Terminal. Model-server variables (`ANTHROPIC_BASE_URL` etc.) stay in the user's own environment or `~/.claude/settings.json`, not in an extension setting (`SETUP.md`). Known limit: VS Code replaces the whole object when the user sets one key, so a user value must list every variable they still want.
- Start: the process is spawned when the webview sends `ready`, then the extension sends the `initialize` control request (60 s timeout). Its response is the source for the `/` commands, the models, the agents and the account: keys `commands[{name, description, argumentHint}]`, `agents`, `output_style`, `available_output_styles`, `models[{value, displayName, description, ...}]`, `account`, `pid`.
- Control requests sent: `initialize`, `interrupt`, `set_permission_mode`, `set_model`, and for MCP management `mcp_status`, `mcp_reconnect` `{serverName}`, `mcp_toggle` `{serverName, enabled}` (see "MCP management"). Received: `can_use_tool` (permission cards). An unknown incoming request is answered with an error response; an outgoing request the CLI rejects is logged and the UI keeps its previous state.
- Stop button: pending permission cards are denied with "Interrupted by the user" and `interrupt` is sent; a process still alive 6 s later is killed (`taskkill /T /F` on Windows). A stopped turn shows "■ הופסק" (never an error); if the CLI sends no `result` within 4 s after the interrupt acknowledgement, the turn is closed locally so the stop button never hangs. (Against CLI 2.1.246 the `result` arrives in about 0.5 s and the process stays alive, so the 4 s wait is only a fallback.)
- Bypass mode: switching to `bypassPermissions` works only when the process was launched with `--allow-dangerously-skip-permissions`; `buildArgs` adds that flag when `claudeLocal.allowDangerouslySkipPermissions` is on. A failed `set_permission_mode` / `set_model` shows a Hebrew notice and the UI keeps the previous value.
- Failures add a Hebrew error to the conversation: spawn failure ("לא ניתן להפעיל את Claude (…). בדוק את ההגדרה claudeLocal.claudePath."), unknown option ("גרסת Claude Code לא מכירה אחד הדגלים שהתוסף שלח."), else exit code + the last 3000 characters of stderr. When the process exits with an error, a Hebrew error card follows the error line (see "CLI failure card").
- Control requests sent: `initialize`, `interrupt`, `set_permission_mode`, `get_context_usage` (after initialize and after each result). `set_model` is no longer sent: a model change restarts the process. Received: `can_use_tool` (permission cards). An unknown incoming request is answered with an error response; an outgoing request the CLI rejects is logged and the UI keeps its previous state.
- Stop button: pending permission cards are denied with "Interrupted by the user" and `interrupt` is sent; a process still alive 6 s later is killed (`taskkill /T /F` on Windows). A stopped turn shows "■ הופסק" (never an error); if the CLI sends no `result` within 4 s after the interrupt acknowledgement, the turn is closed locally so the stop button never hangs. (Against CLI 2.1.246 the `result` arrives in about 0.5 s and the process stays alive, so the 4 s wait is only a fallback.)
- Bypass mode: switching to `bypassPermissions` works only when the process was launched with `--allow-dangerously-skip-permissions`; `buildArgs` adds that flag when `claudeLocal.allowDangerouslySkipPermissions` is on. A failed `set_permission_mode` shows a Hebrew notice and the UI keeps the previous value.
- Failures add a Hebrew error to the conversation: spawn failure ("לא ניתן להפעיל את Claude (…). בדוק את ההגדרה claudeLocal.claudePath."), unknown option ("גרסת Claude Code לא מכירה אחד הדגלים שהתוסף שלח."), else exit code + the last 3000 characters of stderr.
- Every line in and out is logged at debug level to the OutputChannel, message contents cut to 500 characters.
- Lifetime: killed when its conversation is closed (drawer) or the extension deactivates; not when the view or tab that shows it is disposed (see "Placement").
- Code: `src/cli/` (`args.js`, `spawn.js`, `env.js` (environment merge), `terminal.js`, `process.js` with `send`/`request`/`respond`/`respondError`/`interrupt`/`kill`, `content.js`), `dev/fake-claude.js` (+ `.cmd`; `dev/README.md`), `test/args.test.js`, `test/env.test.js`, `test/process.test.js`.

## Chat webview
- One HTML shell for both surfaces (`webview/chat/index.html`), `dir="rtl" lang="he"`. Layout and visual language mirror the official extension: a header (start side: the drawer button ☰ and the title; end side: MCP and "new conversation"), a scrolling thread (empty state: the mascot, the "Claude Code" wordmark and an "איך מתחילים" tips card), a composer at the bottom with a footer row ("+" menu (attach an image through a file picker, or insert "@"), a "/" button, the model pill, the mode as icon + label, the context meter, stop/send). Styles are split by topic: `chat.css` (tokens, header, thread), `composer.css`, `drawer.css`, `cards.css`, `mcp.css`. It stays usable down to 280 px wide in light and dark themes. Known differences from the official look: no Local/Web tabs, no mic/bookmarks/effort/learn icons (all decided); the drawer replaces the official popover (decided); the mode icons are text glyphs, not the official SVGs; the send button's hover colour is a guess; the permission prompt stays in the thread (the official one may dock above the composer); fonts and sizes are approximated from screenshots. Colors come only from VS Code theme variables (`--vscode-editor-background`, `--vscode-foreground`, `--vscode-button-*`, `--vscode-textCodeBlock-background`, …) so it follows light, dark and high-contrast themes. Fonts: the editor/UI fonts via `--vscode-font-family` / `--vscode-editor-font-family`.
- Direction: the shell is RTL; code, paths, commands and tool names are LTR islands (`dir="ltr"`, `unicode-bidi: isolate`); message paragraphs use `dir="auto"` so English text reads correctly.
- Security: CSP `default-src 'none'; img-src ${webview.cspSource} data:; style-src ${webview.cspSource}; script-src 'nonce-<random>'; font-src ${webview.cspSource}`; `localResourceRoots` = `webview/` and `resources/` only; `enableScripts: true`, `retainContextWhenHidden: true` (a hidden tab keeps streaming).
- Host <-> webview messages (`postMessage`, every message `{type, ...}`):

  | Direction | type | Payload |
  |---|---|---|
  | webview -> host | `ready` | — (host spawns the process, replies with `init`) |
  | host -> webview | `init` | initial state (settings, modes, session) |
  | host -> webview | `settings` / `notice` | live setting values; a Hebrew notice line (e.g. a failed `set_model`) |
  | host -> webview | `commands` / `models` | from the `initialize` response (sent when it arrives) |
  | host -> webview | `mode` / `model` | the value the CLI confirmed (or the previous one after a failure) |
  | webview -> host | `send` | `{text}` |
  | webview -> host | `interrupt` | — |
  | webview -> host | `setMode` / `setModel` | `{value}` |
  | host -> webview | `events` | a batch of translated stream events (text delta, thinking, tool start/result, assistant message end, result, error) |
  | host -> webview | `busy` | turn running or finished |
  | host -> webview | `permission` | `{requestId, tool, input, toolUseId, suggestions (bool), reason}` |
  | host -> webview | `permissionCancelled` | `{requestId}` (denied on stop) |
  | webview -> host | `permissionAnswer` | `{requestId, behavior: allow\|deny, always?, message?, updatedInput?}` |
  | host -> webview | `focus` | focus the composer. (`reset` was removed in Fix 1: a new or switched conversation arrives as `restore`.) |
  | host -> webview | `restore` | redraw the thread, bars, pending permission/queue state of the conversation now shown, in one pass, from its in-memory replay log (sent on every switch) |
  | host -> webview | `conversations` / `conversationStates` / `title` | the drawer's list (open conversations with status, past conversations `{id, title, mtime}`); status changes only (sent when running/waiting/unread changes); the shown conversation's title |
  | webview -> host | `listConversations` | asks for the drawer list (the log line `[history] drawer: N open, M past`) |
  | webview -> host | `newConversation` / `switchConversation` / `closeConversation` / `renameConversation` | drawer and header actions, routed by `ConversationHost` (rename sends `/rename <title>` to the CLI as user text) |
  | webview -> host | `openSession` | `{id}`: a past conversation. Shown in the empty current conversation if there is one, else in a new one; an already open session is switched to |
  | webview -> host | `viewFocus` | the chat gained/lost focus (feeds `focusToggle`) |
  | host -> webview | `sessionLoaded` | `{id, items}` (earlier messages read from the transcript) |
  | webview -> host | `openFile` | `{path, line?}` (file paths in tool rows) |
  | webview -> host | `openLink` | `{url}` (http/https only) |
  | webview -> host | `mcp` | `{action: status\|reconnect\|toggle\|add\|remove, ...}` (MCP dialog) |
  | host -> webview | `mcpState` / `mcpResult` | the normalized server list; the outcome of an action (Hebrew text) |
  | webview -> host | `openSettings` | opens `settings.json` or the `claudeLocal.claudePath` setting (card buttons) |
  | host -> webview | `errorCard` | the CLI-failure card data (see "CLI failure card") |

- Thread content:
  - User messages.
  - Assistant text streamed token by token and rendered as Markdown with `marked`: headings, lists, tables, blockquotes, links, inline code, fenced code. Raw HTML in Markdown is escaped, never injected; links are opened only through the host (`openLink`, http/https).
  - Fenced code blocks: LTR, highlighted with `highlight.js`, a language label and a copy button.
  - Thinking: collapsed by default, expandable. (The local model produces no thinking blocks.)
  - Tool rows: tool name + a one-line summary (file path, command, pattern), expandable to the full input and the result; file paths open the file.
  - Result line when the `result` message arrives: duration and tokens ("תור: קלט X · פלט Y"), each only when given. No cost (the CLI's cost is meaningless with a local model; removed in package D).
  - Context meter in the composer (`webview/chat/context-meter.js`): **display only**, a percentage ("37%") with a tooltip holding the numbers (`totalTokens` / `maxTokens` from `get_context_usage`), refreshed after each result; warning colour from 70%, danger from 85%. A click does nothing (F-10: it used to send `/compact`; `/compact` stays available as a typed command). The window is `CLAUDE_CODE_MAX_CONTEXT_TOKENS` from `environmentVariables`.
  - Errors in Hebrew (see "Process & protocol").
  - During a turn a spinner with a Hebrew verb ("חושב…") and the stop button.
- Composer: by default Enter sends and Shift+Enter is a new line. The keys come from the settings `claudeLocal.keybindings.send` / `newLine` / `rewind` (defaults `Enter`, `Shift+Enter`, `Escape Escape`; a key combination like `Ctrl+Enter` or a space-separated sequence), matched in the webview (not read from VS Code's keybindings). `claudeLocal.useCtrlEnterToSend` stays for compatibility and swaps the `send` and `newLine` defaults (Ctrl+Enter sends, Enter is a new line); it applies only while the two settings are at their defaults. The `rewind` key is parsed and matched but only fires the hook `CL.composer.onRewind`; the action arrives with checkpoints (package B). While a turn runs the send button becomes stop. Footer: "+" menu, "/" button, model pill, mode, context meter. The composer's own state (draft, the client-side queue, prompt history) is saved and restored on a conversation switch (`composer.js` `uiState`/`restore`; the host keeps it in `Conversation.ui`, cleared on `attach` so a stale queue is never re-sent); the queue of a hidden conversation is sent by the host when its turn ends (`[queue] send next queued (hidden conversation …)`).
- Model pill (`composer.js`; the separate `model-picker.js` was removed): the first choice is "ברירת מחדל" (the CLI default, no `--model`), then the gateway's model ids (`GET <base>/v1/models` + `/v1/model/info`, 5 s timeout, in memory; base = `claudeLocal.gatewayUrl`, else `ANTHROPIC_BASE_URL` from `environmentVariables`, the process environment, or `~/.claude/settings.json` `env`, last). Hidden: models with `litellm_params.extra_body.output_config.format` and those in `claudeLocal.modelDenylist`. If the fetch fails, the current model stays, a Hebrew notice is shown and the fetch is retried at the next process start. A change kills the process and restarts it with `--model <id>`, `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL=<id>` and `--resume <sessionId>`. A result with "does not support tools" shows a Hebrew notice and restarts once on the previous model.
- During a turn the mode picker is disabled and the model pill becomes "stop and switch" (the host also refuses `setModel` / `setMode` with a Hebrew notice). Choosing a model then shows the modal Hebrew warning (partial answer lost, a running tool cut mid-way so a file may be half-written, a pending permission request denied), interrupts, and switches when the turn ends. ## History (past conversations)
The CLI's transcripts are the only store; the extension reads them read-only (user decisions).
- Source: `~/.claude/projects/<encoded cwd>/*.jsonl` (`CLAUDE_CONFIG_DIR` respected; the cwd is encoded by replacing every non-alphanumeric character with `-`; checked: "C:\AI projects\X" becomes "C--AI-projects-X") for the conversation's `cwd`. Per file: id (file name without `.jsonl`), title, last activity (file mtime). Title rule: the CLI's own custom title (set by `/rename` or the app) wins, then a `summary` line, then the first real user message (60 characters). Titles can appear late in a file, so the head and the tail (64 KB each) are read. Newest first; no message count (would need a full read).
- **The conversation drawer (Fix 1, replaces the "שיחות קודמות" header button and the Activity Bar sessions view):** the ☰ button in the chat header opens a drawer sliding in from the start side (`webview/chat/drawer.js`, `drawer.css`, pure `drawer-logic.js`). It holds a segmented filter (הכול / פעילות / ממתינות / הסתיימו), a search box (by title), the section "פתוחות" (the place's open conversations, each with a status dot: running = orange pulsing, waiting for permission = blue, finished unread = orange; click switches; a pencil renames; ✕ closes, with a "לסגור?" confirmation while it runs) and the past conversations of the folder grouped "היום", "אתמול", "השבוע", "קודם" with short times. Empty state: "אין שיחות קודמות בתיקייה הזו". The Activity Bar container `claude-local-history`, the TreeView `claudeLocalHistory` and the commands `history.open/refresh/filter/rename` were removed; the "continue the last conversation" suggestion row is now the command `claude-local.continueLast`.
- Rename sends `/rename <title>` as ordinary user text to the CLI (a conversation that is not open is resumed first); the extension never writes a transcript. Known limit: for a running conversation the `/rename` text queues behind the running turn. Reopen closed: an in-memory list (max 10, session id and title only, lost on reload) behind Ctrl+Shift+T, bound only when `claude-local:hasClosed && (activeWebviewPanelId == 'claudeLocalPanel' || activeEditor == '')` so VS Code's own reopen-closed-editor keeps working for files (`hasClosed` is now set in `commands.js`; with the sidebar as the default place, the `when` clause still names the editor tab and a focused sidebar view is **not** covered: unverified). Filters, the closed list and the status markers are in-memory state only (allowed by "Purpose & principles"); nothing is persisted.
- Opening a past conversation: the earlier messages are read from its jsonl and rendered with the same renderer as live ones (user text, assistant text as Markdown, thinking, tool rows; sidechain, meta and system-injected entries skipped), then the process is started with `--resume <id>` so the next message continues it.
- Where it opens (replaces the old "new editor tab" rule): in the same place. If the current conversation is empty (no messages) it is reused (`[session] open session <id> in the empty conversation c1`); otherwise a new conversation is created for it and shown, and the previous one keeps running in the background. If the same session id is already open in this place, that conversation is switched to instead (an in-memory check only).

## Code navigation MCP server (package H prototype)
Lets Claude navigate JS/React code by symbol instead of text search, with small answers for the 64,000-token window. Design and reasons: `PLAN.md` section 8.
- **Server** (`src/mcp/nav-server.js`): started per CLI process, HTTP on `127.0.0.1`, port 0 (random), random Bearer token (401 without it), hand-written JSON-RPC (`initialize`, `ping`, `tools/list`, `tools/call`; notifications answered 202). Starts asynchronously; the CLI is launched once it listens. If it fails to start, the CLI is spawned without it.
- **Config** (`src/mcp/nav-config.js`): passed inline as `--mcp-config '<JSON>'` (no file written, so the "writes no files" rule holds), server name `claude-local-nav`, with `--allowedTools mcp__claude-local-nav` so the read-only tools need no approval card. Other MCP servers still ask.
- **Tools** (`src/mcp/nav-tools.js`; the only file that requires `vscode` is `nav-vscode.js`, which supplies the dependencies): `documentSymbols` (`vscode.executeDocumentSymbolProvider`), `readSymbol` (symbol range + file read), `findReferences` (`vscode.executeReferenceProvider`); batch 2 (2026-11-06): `goToDefinition` (`vscode.executeDefinitionProvider`, handles Location and LocationLink, target file + line + a few declaration lines, workspace-only, de-duplicated) and `findImporters` (primary: the reference provider on the module's export name; fallback: workspace text search for `import`/`require` lines; each hit tagged `[ref]` or `[text]`; accuracy unchecked). `documentSymbols` drops entries named `<unknown>` and export-shorthand property duplicates but keeps real properties. Text-search lines are 1-based. Batch 3 (2026-11-06) completes the set of eight tools: `workspaceSymbols` (name search with a `kind` filter function/class/variable, workspace-only), `hover` (plain text, capped 2,000 chars, "no hover info" when empty) and `callHierarchy` (`direction` incoming|outgoing; non-empty results carry the note "call hierarchy is less reliable in dynamic JavaScript"; the note is appended after the cap, so a capped answer can exceed 2,000 characters by about 50). Input by `file` + `symbol` (an optional `line` is accepted but not in the schema); a relative path resolves against the first workspace folder.
- **Rules:** at most 50 results and 2,000 characters per answer, ending with "N more not shown"; a path outside the workspace folders answers "no access"; `findReferences` drops results outside the workspace; a language with no provider fails plainly (Claude falls back to `Grep`); tool errors are returned as `isError` results.
- **Transport:** http and stdio both passed the pre-check against the real CLI 2.1.246 (reported by the user, run on another machine; the report file is not in the repo). http is used.
- **Known limits / not verified:** (1) inline `--mcp-config` against the real CLI 2.1.246 (if rejected, a temp config file is needed, a documented exception in `DECISIONS.md`); (2) the three tools in real VS Code; (3) `.cmd` quoting of the inline JSON; (4) `isInsideWorkspace` does not resolve symlinks; (5) the token is visible in the child's command line (loopback only, one process lifetime); (6) the token cost of the tool list was not cleanly measured; whether the local model prefers these tools is unchecked.
- Code: `src/mcp/nav-server.js`, `nav-config.js`, `nav-tools.js`, `nav-vscode.js`; `src/cli/process.js`; `test/nav-server.test.js`, `test/nav-tools.test.js`.
