# Spec — Claude Code Local (VS Code extension), as built

What the extension is and does today (the "basic version", v0.1.0, plus the packages of `PLAN.md` section 5). Decisions: `DECISIONS.md`; roadmap and reasons: `PLAN.md`; CLI/environment findings: `DEPENDENCIES.md`; setup: `SETUP.md`; one line per file (the files behind each section below): `PROJECT_MAP.md`. Verification status of everything: last section.

## Purpose & principles
- A VS Code extension that looks and behaves as close as possible to the official Claude Code extension: send a question, get the answer, render all formatting (Markdown, highlighted code, thinking, tool rows). Basics: conversation history of the open folder, the CLI's skills/commands, permissions, model and mode. The UI mirrors the official layout and visual language (see "Chat webview").
- **The CLI is the only source of truth; the extension is a front, not a store** (user decision). No `globalState`, no `workspaceState`, no files it writes (one explicit exception: the temporary IDE lock file, see "IDE server"), no archive, groups, unread flags, local renames, or reload-restore state. Everything shown is live from the running CLI process or read read-only from the CLI's transcript files. In-memory state that dies with the window (open conversations and replay logs, pending permission cards, unread/running markers, the closed list, recent files) is allowed; persisting it is not.
- The extension never talks to a model; the CLI does. The CLI decides about permissions; the extension only relays.

## Platform constraints
- A small extension of its own; nothing is copied from the older OneDrive project (user decision).
- Runs on Windows with VS Code and the real `claude` CLI (development also uses Node 22). Must run on an offline machine: no CDNs or remote fonts, no network from the webviews. The extension host has two read-only, in-memory exceptions to the user's own servers: the gateway's `GET /v1/models` and `/v1/model/info` (package D, `DECISIONS.md` 2026-11-01) and Ollama's `GET /api/ps` (usage gauge, `DECISIONS.md` 2026-11-08).
- Plain JavaScript only: CommonJS in the extension host, plain `<script>` files in the webview. No TypeScript, no `npm install`, no build step, no bundler.
- Third-party code: only vendored plain-JS files at a pinned version with license files, under `webview/vendor/` (`marked`, `highlight.js`, KaTeX; `DEPENDENCIES.md` section 1). Everything else is hand-written.
- `engines.vscode`: `^1.91.0` (VS Code 1.91.1 on the user's machine did not load the extension with the original `^1.94.0`). The secondary-sidebar container is used from 1.106 (the official extension's threshold, `src/util/vscode-version.js`); older versions fall back to the activity bar.
- The CLI is not bundled; it comes from `claudeLocal.claudePath` (default `claude`; on the user's machine the real `claude-bin.exe`, `SETUP.md`). Target CLI 2.1.181 or newer (built against 2.1.181; the user's machine runs 2.1.246). A bare name is resolved by scanning PATH x PATHEXT; a `.cmd`/`.bat` is run through `cmd.exe /d /s /c`.
- `capabilities.untrustedWorkspaces.supported: false` (no Restricted Mode).
- Ids are renamed so the extension installs next to the official one: commands `claude-local.*`, settings `claudeLocal.*`, views `claudeLocal*`, view containers `claude-local-*`, context keys `claude-local.*`.
- Code is separated by feature: a folder per topic under `src/` and `webview/`.
- **Shortcuts** (decided 2026-11-05): VS Code-level shortcuts are `contributes.keybindings`, so they are rebindable in VS Code's shortcut editor; the command "Claude Code Local: Keyboard Shortcuts" opens `workbench.action.openGlobalKeybindings` filtered to `claude-local`. Ctrl+Shift+Esc (Windows Task Manager) was removed; Ctrl+Alt+C opens the chat; Ctrl+Esc (Windows Start menu) was replaced by Ctrl+Alt+E for `claude-local.focusToggle`. The editor/title button, the status-bar item and the command palette are also entry points. Shortcuts inside the chat webview are separate: the `claudeLocal.keybindings.*` settings (see "Chat webview").

## Manifest & package layout

No `icon` field (no PNG exists; the mascot SVGs are used: `resources/claude-mascot.svg` full colour for the editor-title button and tab, `claude-mascot-mono.svg` `currentColor` for view containers; the spark `claude-logo.svg` was removed). `activationEvents`: `onUri` and `onStartupFinished` (the status-bar item and context keys must exist before anything is opened; commands and views activate implicitly). `contributes` keys: `configuration`, `commands`, `keybindings`, `viewsContainers`, `views`, `menus`.

## Placement
One place, one rule (user decision 2026-11-02, `DECISIONS.md`). A single **place** hosts several conversations, one visible at a time, each with its own CLI process. The rule lives in `src/panels/places.js` (`places.main()`).
- **Default place: the sidebar view** (`claudeLocal.preferredLocation` = `sidebar`); the alternative is **one** editor tab (`panel`): a `WebviewPanel`, viewType `claudeLocalPanel`, mascot icon, title "Claude" (the active conversation's title with a marker). An existing place is focused, never duplicated: never a second tab. With `claudeLocal.lockEditorGroups` the tab's group is locked after creation.
- **Main button** (`claude-local.open`: editor/title button, status-bar item, Ctrl+Alt+C): reveals/focuses the place named by `preferredLocation` and, with `claudeLocal.useTerminal`, opens the CLI in a terminal instead. The URI handler uses the same `places.main()`.
- **Sidebar view:** `claudeLocalSidebarSecondary` in the `secondarySidebar` container `claude-local-sidebar-secondary` (shown when `!claude-local:doesNotSupportSecondarySidebar`) and `claudeLocalSidebar` in the `activitybar` container `claude-local-sidebar` (shown when it is true, the fallback for old VS Code). At activation the extension sets that context key from `vscode.version`. Both views are `type: webview`. The `ConversationHost` outlives the `WebviewView`: when the view is disposed or hidden the conversations and processes keep living.
- **Several conversations in one place** (`src/panels/conversation-host.js`; exactly one attached to the webview). "New conversation" while another runs (or waits for a permission) creates a new one and shows it; the other **keeps running in the background** (process not interrupted). The webview is redrawn from in-memory state on every switch (`replay-log.js` records what a hidden conversation would have shown, folding streamed deltas per block; the `restore` message redraws in one pass). A permission request or question arriving while hidden stays pending and is signalled; a turn that ends while hidden marks the conversation unread. Nothing persisted. Root cause fixed (F-2): `Conversation.newConversation()` returned early when `busy`; `newConversation`, `openSession`, `listHistory` and `openInNewTab` no longer exist on `Conversation`.
- **Signals for hidden conversations (in memory):** drawer status dots (running = orange pulsing, waiting for permission = blue, finished unread = orange); in the sidebar `view.badge` = number of hidden waiting + unread conversations and the view description = the title; in the editor tab a title prefix blue circle (waiting) / orange circle (finished unseen), because VS Code has no tab colour API. **Tab dots exist only with `preferredLocation=panel`; with the default `sidebar` the signals are the drawer dots and the view badge (by design, not a bug).**
- Commands (palette titles keep the English "Claude Code Local:" prefix plus a Hebrew title; every webview string is Hebrew). Removed in Fix 1: `editor.open`, `editor.openLast`, `sidebar.open`, `history.open`, `history.refresh`, `history.filter`, `history.rename`.

  **Logging.** Every line is `HH:MM:SS.mmm [WARN|ERROR] [tag] text`; tags are fixed per feature (`src/util/log-tags.js`: spawn, stream, permission, queue, history, session, mcp, uri, error-card, model-switch, context, checkpoint, diff, tasks, background, display, settings, control, general; later also agents, loop, drop, btw, ide). Setting `claudeLocal.logLevel`: `info` (default) or `debug` (adds a type/size summary of every stream line). - Status bar: a right-side item "✻ Claude" running `claude-local.open`; works without an open file.
- Lifetime: closing a conversation (the drawer's close button, which asks "לסגור?" while a turn runs) kills its process and puts it on the closed list. Disposing the sidebar view or closing the editor tab does **not** kill anything; all processes die when the extension deactivates. Nothing is restored after a window reload (no `WebviewPanelSerializer`); conversations are reachable again through the drawer's past conversations.

## Process & protocol
One long-lived CLI process per conversation, over stdin/stdout with stream-json and the control protocol (user decision).
- Spawn: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio --permission-mode <mode>`, plus `--resume <sessionId>` to continue a past conversation, `--model <m>` when the user picked one, `--allow-dangerously-skip-permissions` when `claudeLocal.allowDangerouslySkipPermissions` is on, and `--settings <json>` with an `env` object when there is something to override (`src/models/launch.js`): every model alias (`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`) set to the picked model and, when `environmentVariables` holds a positive integer `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, that value plus `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. These go through `--settings` because the CLI applies the `env` of its settings files over its process environment and `--settings` over `~/.claude/settings.json` (F-8, F-9; `DEPENDENCIES.md` #39, #40). Every spawn also gets `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=1` and `--replay-user-messages` (checkpoints). The navigation server adds `--mcp-config <inline JSON>` and `--allowedTools mcp__claude-local-nav` (no `--strict-mcp-config`, so the user's other MCP servers still load); if that server fails to start the CLI is spawned without them. No capability probing: the target CLI is fixed (2.1.181+); an unknown-flag failure is reported in Hebrew.
- `cwd`: the first workspace folder. No folder open: the user's home, and the composer shows "לא נפתחה תיקייה – Claude עובד בתיקיית הבית".
- Environment: `process.env`, then `claudeLocal.environmentVariables` merged over it (defaults `API_TIMEOUT_MS=1200000`, `CLAUDE_ENABLE_STREAM_WATCHDOG=0`, `CLAUDE_CODE_MAX_CONTEXT_TOKENS=64000`; values coerced to strings, invalid entries ignored; applies from the next process start), then `CLAUDE_CODE_ENTRYPOINT=claude-local-vscode`; plus `CLAUDE_CODE_SSE_PORT` when the IDE server runs. Open in Terminal uses the same merged environment without `--settings` (so the terminal CLI still starts on `[1m]`). Precedence caveat: a variable that `~/.claude/settings.json` `env` also sets keeps the settings.json value inside the CLI, except those passed through `--settings`. Model-server variables (`ANTHROPIC_BASE_URL` etc.) stay in the user's own environment or `~/.claude/settings.json` (`SETUP.md`). Known limit: VS Code replaces the whole object when the user sets one key, so a user value must list every variable they still want.
- Start: spawned when the webview sends `ready`, then the `initialize` control request (60 s timeout). Its response is the source for the `/` commands, models, agents and account: `commands[{name, description, argumentHint}]`, `agents`, `output_style`, `available_output_styles`, `models[{value, displayName, description, ...}]`, `account`, `pid`.
- Control requests sent: `initialize`, `interrupt`, `set_permission_mode`, `get_context_usage` (after initialize and each result), `stop_task`, `rewind_files`, and for MCP `mcp_status`, `mcp_reconnect {serverName}`, `mcp_toggle {serverName, enabled}`. `set_model` is no longer sent: a model change restarts the process. Received: `can_use_tool` (permission cards). An unknown incoming request is answered with an error response; an outgoing request the CLI rejects is logged and the UI keeps its previous state.
- Stop button: pending permission cards are denied with "Interrupted by the user" and `interrupt` is sent; a process still alive 6 s later is killed (`taskkill /T /F` on Windows). A stopped turn shows "■ הופסק" (never an error); if no `result` arrives within 4 s after the interrupt acknowledgement the turn is closed locally so stop never hangs. (Against CLI 2.1.246 the `result` arrives in about 0.5 s and the process stays alive, so 4 s is only a fallback.)
- Bypass mode: switching to `bypassPermissions` works only when the process was launched with `--allow-dangerously-skip-permissions`. A failed `set_permission_mode` shows a Hebrew notice and the UI keeps the previous value.
- Failures add a Hebrew error to the conversation: spawn failure ("לא ניתן להפעיל את Claude (…). בדוק את ההגדרה claudeLocal.claudePath."), unknown option ("גרסת Claude Code לא מכירה אחד הדגלים שהתוסף שלח."), else exit code + the last 3000 characters of stderr; on an error exit a Hebrew error card follows (see "CLI failure card").
- Lifetime: see "Placement".

## Chat webview
- One HTML shell for both surfaces (`webview/chat/index.html`), `dir="rtl" lang="he"`. Layout: a header (start side: drawer button ☰ and title; end side: MCP and "new conversation"), a scrolling thread (empty state: the mascot, the "Claude Code" wordmark and an "איך מתחילים" tips card), a composer at the bottom with a footer row ("+" menu (attach an image through a file picker, or insert "@"), a "/" button, the model pill, the mode as icon + label, the usage gauge, stop/send). Styles by topic: `chat.css` (tokens, header, thread), `composer.css`, `drawer.css`, `cards.css`, `mcp.css`, `a11y.css`. Usable down to 280 px wide in light and dark themes. Colors come only from VS Code theme variables (`--vscode-editor-background`, `--vscode-foreground`, `--vscode-button-*`, `--vscode-textCodeBlock-background`, …), so it follows light, dark and high-contrast themes; fonts via `--vscode-font-family` / `--vscode-editor-font-family`.
- **Official look (2026-11-09):** tokens and component rules of the official extension anthropic.claude-code 2.1.319 (`webview/index.css`, read locally and re-expressed in our own CSS; no file copied) are followed in `chat.css`, `composer.css`, `cards.css`, `a11y.css`: tokens `--cl-active-border`, `--cl-pill-bg/-hover`, `--cl-chip-bg`, `--cl-clay` (#c6613f), `--cl-ivory` (#faf9f5), `--cl-chat-size`, `--cl-timeline-line`; border chain `inlineChatInput-border` -> `input-border` -> `widget-border` -> `#7f7f7f66`; composer with a soft shadow and an orange focus ring; the send button is the clay-orange square whose colour follows the permission mode (`sendBtn.dataset.mode`); menus in the official picker look; chips as grey attachment pills (✕ fades in on hover); compact user messages. The file and lines chips stay above the text (user decision). **Theme:** follows the VS Code theme like the official extension; no forced dark mode, no theme setting.
- Known differences from the official look (all decided unless marked): no Local/Web tabs, no mic/bookmarks/effort/learn icons; the drawer replaces the official popover; mode icons are text glyphs, not the official SVGs; the send button's hover colour is a guess (not decided); the permission prompt stays in the thread (the official one may dock above the composer); fonts and sizes approximated from screenshots (before the 2.1.319 restyle).
- Direction: the shell is RTL; code, paths, commands and tool names are LTR islands (`dir="ltr"`, `unicode-bidi: isolate`); message paragraphs use `dir="auto"`.

- Thread content:
  - User messages. Assistant text streamed token by token and rendered as Markdown with `marked`: headings, lists, tables, blockquotes, links, inline code, fenced code. Raw HTML in Markdown is escaped, never injected; links open only through the host (`openLink`, http/https).
  - Fenced code blocks: LTR, highlighted with `highlight.js`, language label and copy button.
  - Thinking: collapsed by default, expandable (the local model produces none).
  - Tool rows: tool name + one-line summary (file path, command, pattern), expandable to the full input and result; file paths open the file.
  - Result line when the `result` arrives: duration and tokens ("תור: קלט X · פלט Y"), each only when given. No cost (meaningless with a local model; removed in package D).
  - Errors in Hebrew (see "Process & protocol"). During a turn a spinner with a Hebrew verb ("חושב…") and the stop button.
- **Usage gauge** in the composer (2026-11-08, replaces the context meter's text; `webview/chat/usage-gauge.js`, pure `usage-gauge-logic.js`, host `src/panels/context-meter.js`): a small ring (SVG, `pathLength` 100) plus "37%" (the number hides below 340 px), refreshed after `initialize` (so after a model switch too) and after each result; neutral colour, `--vscode-charts-orange` from 70%, `--vscode-errorForeground` from 85%. Hover (250 ms) previews; click or Enter/Space keeps open a card in the style of the Claude app's "Context" panel: title "הקשר" with "N% בשימוש", "used מתוך max אסימונים", a stacked bar, rows with tokens and percent of the window (one decimal) for הודעות, הנחיית מערכת, כלי מערכת, כלי MCP, סוכנים מותאמים, מיומנויות (Skills), קובצי זיכרון, then "שמור לכיווץ אוטומטי" and "מקום פנוי" recomputed against the window; deferred tools (tokens only), the count of memory files and of MCP servers (distinct `mcpTools[].serverName`), the window source and a `/compact` hint. Category colours are VS Code chart/terminal colours. Escape or an outside click closes it. Display only (F-10: no `/compact` on click). Tokens only. **The window:** Ollama `GET /api/ps` `models[].context_length` of the entry matching the CLI's model name (`[1m]` and a provider prefix dropped; the last value per model is kept in memory while Ollama has it unloaded), else `CLAUDE_CODE_MAX_CONTEXT_TOKENS` from `environmentVariables`, else the CLI's `maxTokens`; the chosen window is a ceiling on the CLI's `maxTokens`; the log line says `source=ollama|settings|cli` and `(CLI max=…, capped)`. The Ollama read is a network exception approved by the user (`DECISIONS.md` 2026-11-08).
- Composer: Enter sends and Shift+Enter is a new line by default. Keys come from `claudeLocal.keybindings.send` / `newLine` / `rewind` (defaults `Enter`, `Shift+Enter`, `Escape Escape`; a combination like `Ctrl+Enter` or a space-separated sequence), matched in the webview (not read from VS Code's keybindings). `claudeLocal.useCtrlEnterToSend` stays for compatibility and swaps the `send`/`newLine` defaults; it applies only while the two settings are at their defaults. `rewind` opens the checkpoints menu (see "Skills / commands menu"). While a turn runs the send button becomes stop. The composer's state (draft, client-side queue, prompt history) is saved and restored on a conversation switch (`composer.js` `uiState`/`restore`; the host keeps it in `Conversation.ui`, cleared on `attach` so a stale queue is never re-sent); a hidden conversation's queue is sent by the host when its turn ends (`[queue] send next queued (hidden conversation …)`).
- Model pill (`composer.js`): first choice "ברירת מחדל" (CLI default, no `--model`), then the gateway's model ids (`GET <base>/v1/models` + `/v1/model/info`, 5 s timeout, in memory; base = `claudeLocal.gatewayUrl`, else `ANTHROPIC_BASE_URL` from `environmentVariables`, the process environment, or `~/.claude/settings.json` `env`, last). Hidden: models with `litellm_params.extra_body.output_config.format` and those in `claudeLocal.modelDenylist`. If the fetch fails the current model stays, a Hebrew notice is shown and the fetch is retried at the next process start. A change kills the process and restarts it with `--model <id>`, every alias set to `<id>` through `--settings` (so the session-title call does not load a second model) and `--resume <sessionId>`. A result with "does not support tools" shows a Hebrew notice and restarts once on the previous model.
- During a turn the mode picker is disabled and the model pill becomes "stop and switch" (the host also refuses `setModel`/`setMode` with a Hebrew notice). Choosing a model then shows the modal Hebrew warning (partial answer lost, a running tool cut mid-way so a file may be half-written, a pending permission request denied), interrupts, and switches when the turn ends.
- Permission card: see "Permissions & modes". MCP dialog: header with refresh and close icon buttons, status dots, Esc or an outside click closes. Background-task and `/loop` bars: a small square stop icon button (`CL.tasksBar.stopButton`).

## Code navigation MCP server (package H prototype; later "J")
Lets Claude navigate JS/React code by symbol instead of text search, with small answers for the 64,000-token window. Design and reasons: `PLAN.md` section 8.
- **Server** (`src/mcp/nav-server.js`): per CLI process, HTTP on `127.0.0.1`, port 0 (random), random Bearer token (401 without), hand-written JSON-RPC (`initialize`, `ping`, `tools/list`, `tools/call`; notifications answered 202). Starts asynchronously; the CLI is launched once it listens; if it fails to start the CLI is spawned without it. **Config** (`nav-config.js`): inline `--mcp-config '<JSON>'` (no file written), server name `claude-local-nav`, with `--allowedTools mcp__claude-local-nav` so these read-only tools need no approval card; other MCP servers still ask.
- **Tools** (`src/mcp/nav-tools.js`; only `nav-vscode.js` requires `vscode` and supplies the dependencies). Every answer comes from VS Code's own providers; the tool layer finds the position, makes the language server load the files, waits for it, and shapes the answer:
  - `documentSymbols` (`vscode.executeDocumentSymbolProvider`): outline in line order: top-level symbols, class and object members; no locals; a variable whose value is a function (`const Button = () => ...`) is listed and filtered as `function`; `<unknown>` and export-shorthand property duplicates dropped. `kind` filter function/class/variable.
  - `readSymbol`: the symbol's lines (range + file read). A name only imported answers "not declared in this file; goToDefinition finds where it is".
  - `findReferences` (`vscode.executeReferenceProvider`); `goToDefinition` (`vscode.executeDefinitionProvider`, Location and LocationLink, one declaration line per target, workspace-only, de-duplicated; a target outside the workspace answers "defined outside the open workspace folders"); `hover` (`vscode.executeHoverProvider`, plain text without code fences or "(loading...)", 2,000 chars); `callHierarchy` (`vscode.prepareCallHierarchy` + incoming/outgoing; the "less reliable in dynamic JavaScript" note fits inside the 2,000-char cap); `workspaceSymbols` (`vscode.executeWorkspaceSymbolProvider`, `kind` filter, workspace-only).
  - `findImporters`: workspace text search for `from`/`import`/`import()`/`require` lines naming the module's base name (or its folder for `index.*`); a relative specifier counts only when it resolves to the file (Node/bundler rules: extensions, `index.*`, `.js` written for a `.ts` file); a bare or aliased specifier counts only when VS Code's definition provider on the module string leads to the file (`[unverified]` without a provider). Comment lines and strings skipped; a text search that stops at its 500-match limit says so.
- **Finding the position:** input is `file` + `symbol` (+ optional 1-based `line`, in the schema of every symbol tool). Candidates, best first: the declared symbol on that line, any whole-word occurrence on that line, the declared symbol, then every occurrence in code (not comments or plain strings; template-literal code counts). Up to five candidates are tried until the provider answers, so an imported or used-only name works. A definition that stops at an import line of the same file is an alias: the next occurrence is tried; if the language server still cannot follow it (seen: a closed `.jsx` module without `jsconfig.json`), the module path is resolved, opened and asked again, else the name is looked up in that module's symbols. A relative path resolves against the first workspace folder.
- **Cross-file completeness:** before `findReferences` and incoming `callHierarchy`, every workspace JS/TS file that mentions the name (whole word, up to 200 files) is opened in memory (`openTextDocument`, no editor shown), because without `jsconfig.json` the TypeScript server only knows open files and what they import. Each text occurrence the provider did not return is checked with the definition provider (bounded to 100); when it leads to the same declaration it is added (seen: `math.add` after a CommonJS `require` of an ES module). An added call is listed under its innermost named enclosing function.
- **Language server start:** on the first JS/TS call of a process, an empty symbol answer for a non-empty file is polled every 250 ms for up to 20 s; if it never answers the tool says the JS/TS language server has not answered yet (not "use Grep"). After the first answer an empty file answers "no symbols in this file". A file type with no provider answers "no language provider for this file type; use Grep".
- **Rules:** caps, permissions, path limit and plain failure: `PLAN.md` section 8 "Design rules". As built also: `findReferences` drops results outside the workspace; tool errors are `isError` results.
- **Transport:** http and stdio both passed the pre-check against the real CLI 2.1.246 (user report, other machine, report file not in the repo). http is used.
- **Known limits:** a call by a computed name (`m[name]()`) cannot be found by any static tool; `isInsideWorkspace` does not resolve symlinks; the token is visible in the child's command line (loopback only, one process lifetime); if inline `--mcp-config` is rejected by the real CLI a temp config file is needed (documented exception, `DECISIONS.md` 2026-11-05). Verification: last section.

## File tagging: file chip and lines chip (package K, built 2026-11-09)

A manual chip has a stronger neutral border. The lines chip's numbers sit in `<bdi dir="ltr">` so "12–30" is not shown as "30–12". X on a manual choice returns to automatic; X on the automatic chip hides it until the file changes. Icons are inline SVG.
- **Empty chips:** grey hints "אין קובץ" / "אין בחירה" (`chip-empty`); the empty file chip opens the same menu, the empty lines chip is not clickable.
- **Lines chip:** automatic only, shown only when the selection is in the file the file chip holds; sent once per change of the selection (text capped at 8,000 chars); X hides it until the selection changes.
- **Recents** (`src/tagging/recent-files.js`): 5 items, shared by all conversations, in memory. Shown in the chip menu and first in the `@` menu (label "אחרון"). Files picked through `@` and Alt+K join the list; folders picked while drilling the `@` menu do not.
- **`@` and Alt+K** insert text in the box, separate from the chips. A file already mentioned in the text is not repeated by the chip but counts as sent. With no cwd a relative `@x` is not resolved, so the same file may be named twice (rare, harmless).

## Open button, navigation cards, changes card, mid-sentence menus (2026-11-09)
- **Open button:** a tool row is a head button plus a sibling "פתיחה בעורך" button (`.tool-open`), shown only when the row's summary has a path (`Read`, `Edit`, `Write`, and `mcp__claude-local-nav__*` through `navSummary` in `webview/chat/tools.js`). Only the button opens the file (at the line or symbol when known); clicking the summary only expands the row. The editor never moves by itself, and there is no setting. Relative nav paths resolve against the workspace folders, then the cwd (`src/panels/resolve-path.js`, `conversation.openFile`).
- **Navigation cards** (`webview/chat/nav-results.js`, `CL.navResults` parse/title/render): a short Hebrew card per navigation tool result with a title per tool (for example "הפניות ל-…"); up to 50 clickable rows that open the file at that line, then "ועוד N שלא מוצגים". `readSymbol` and `hover` get no card.
- **Changes card** (`src/diff/change-stats.js`, `src/diff/changes-card.js`, `webview/chat/changes-card.js`, `changes-card.css`): a collapsible `<details>` "שינויים בשיחה (N קבצים)" above the composer, hidden when empty, shown in every permission mode. Built from the `Edit`/`Write` entries of the edit log (not from permission cards): per file the added and removed lines (LCS line diff per fragment with prefix/suffix trim, a fallback above 2000x2000 cells; a `Write` is compared to the last known content, else all lines count as added). Clicking a file sends `openChangeDiff {path}`; `conversation.openChangeDiff` accepts only paths in the edit log and opens the diff through the shared `showFileDiff` (`src/diff/diff-command.js`). The card is a replay-log snapshot (`changesCard` in `SNAPSHOT_TYPES`), posted after live edit batches and after a session load, reset on a new conversation and when the user sends exactly `/clear` (the edit log is emptied, so `/diff` restarts too; the text still goes to the CLI).
- **Mid-sentence menus** (`webview/chat/trigger-token.js`, `CL.triggerToken.find(text, caret)`): `/` opens the menu at the text start or after whitespace (not inside `a/b` or `http://`); `@` opens it after whitespace or `( [ { " '` (not inside an e-mail). Local/terminal-only commands keep their special behaviour only when the token is the whole message. Text after the caret is preserved.
- **Known limits:** the stats are recomputed over the whole log on every batch (possible lag in very long sessions); a `Write` to a file never seen counts all lines as added; a mid-sentence path such as `/re` can open the menu so Enter picks a command (Escape closes it); async errors in `openChangeDiff` are not caught by the router (pre-existing pattern).

## IDE server (package F, 2026-11-08; off by default since package K)
- **What:** one server per VS Code window (`src/ide/`): a hand-written RFC 6455 WebSocket server on `127.0.0.1`, random port, random 64-hex token; MCP JSON-RPC (`initialize`, `ping`, `tools/list`, `tools/call`). Tools: `getDiagnostics`, `getOpenEditors`, `openFile` (with `startText`/`endText` selection). Notification `selection_changed` (0-based positions) on every editor-tracker change while a client is connected, and once after `notifications/initialized`. `openDiff` closed 2026-11-09 as redundant, not built (per-block review and the changes card cover it; `DECISIONS.md`).
- **Handshake:** 401 without the token (accepted in `x-claude-code-ide-authorization` or `Authorization`, raw or `Bearer`), 403 for a non-local `Origin` (none is fine), 400/426 for a bad upgrade; subprotocol `mcp` echoed only when offered. Client frames must be masked; fragmentation, ping/pong and close handled; max message 16 MB.
- **Lock file (the one file the extension writes, `DECISIONS.md` 2026-11-08):** `<CLAUDE_CONFIG_DIR or ~/.claude>/ide/<port>.lock` = `{pid, workspaceFolders, ideName, transport:"ws", runningInWindows, authToken}` (mode 0600; on Windows privacy comes from the profile folder's ACL). Removed on dispose, on `ideServer` off and on process exit (only if it still names our pid). On start, a lock is deleted only when its pid is dead AND its port refuses a connection; unreadable locks are left for the CLI.
- **Default off (package K, 2026-11-09):** `claudeLocal.ideServer` is false because the CLI did not connect in stream-json mode ("currently not working"). `src/ide/` is unchanged. The rest describes what happens when the user turns it on.
- **Connecting the CLI:** `startProcess` adds `CLAUDE_CODE_SSE_PORT=<port>` to the child env when the CLI's cwd is one of the lock's workspace folders. If no client connects within 30 s the conversation shows a Hebrew notice; chips keep working either way.
- **Log (tag `ide`):** listening/lock, each handshake (header names; full headers with the token masked in verbose mode), accepted/rejected with the reason, each request method, unknown methods/tools as warnings; verbose mode adds every JSON-RPC message in 450-character parts.
