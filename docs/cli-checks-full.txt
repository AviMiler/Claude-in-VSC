מדריך מלא: בדיקות היתכנות מול ה-CLI של Claude Code
====================================================

הקובץ הזה עומד בפני עצמו. אין צורך בגיטהאב, באינטרנט או בקבצים נוספים.
כל מה שנדרש נמצא כאן: הסברים, הפקודות, והקוד המלא של הסקריפט (בסוף הקובץ).


חלק א. למה עושים את הבדיקות
----------------------------------------------------
אנחנו מתכננים תוסף VS Code בשם "Claude Code Local" שמפעיל את ה-CLI האמיתי של
Claude Code (claude) ומדבר איתו בפרוטוקול stream-json. הוחלט על רשימה גדולה של
פיצ'רים (תפריט פקודות מקובץ, החלפת מודל באמצע עבודה, Checkpoints, תור הודעות,
חיבור MCP, הקשר מהעורך ועוד). חלק מהם תלויים בדברים שאי אפשר לדעת בלי לשאול את
ה-CLI עצמו, כי הוא לא מתועד מספיק: אילו שדות הוא מחזיר, אילו בקשות הוא מכיר,
ואיך הוא מתנהג מול מודל מקומי (Ollama).

לכן הכנו סקריפט אחד שמדבר עם ה-CLI בדיוק כמו שהתוסף יעשה, ורושם בקובץ דוח
(probe-report.json) מה קרה. אחרי שתשלח לנו את הדוח נדע מה אפשר לבנות ומה לא,
ולא נבנה פיצ'רים על הנחות.

כל הבדיקות הן לקריאה בלבד או רצות בתיקייה זמנית. הן לא נוגעות בפרויקטים שלך.


חלק ב. מה צריך לפני שמתחילים
----------------------------------------------------
1. Node.js גרסה 18 ומעלה (מומלץ 22). בדיקה:
       node -v
2. Claude Code CLI מותקן, ומחובר למודל המקומי. בדיקה:
       claude --version
   בפרויקט נרשמה הגרסה 2.1.181 כגרסת יעד; גרסה חדשה יותר גם טובה, פשוט תרשום מה יש.
3. קובץ ההגדרות של ה-CLI מכוון למודל המקומי. הנתיב:
       C:\Users\User\.claude\settings.json
   והתוכן (אם הקובץ קיים כבר, מוסיפים רק את החלק env):

       {
         "env": {
           "ANTHROPIC_BASE_URL": "http://172.27.5.5:11436",
           "ANTHROPIC_AUTH_TOKEN": "ollama",
           "ANTHROPIC_DEFAULT_OPUS_MODEL": "qwen3.8:27b",
           "ANTHROPIC_DEFAULT_SONNET_MODEL": "qwen3.8:27b",
           "ANTHROPIC_DEFAULT_HAIKU_MODEL": "qwen3.8:27b",
           "CLAUDE_DISABLE_TELEMETRY": "1",
           "CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS": "1"
         }
       }

   מה כל שורה עושה:
   - ANTHROPIC_BASE_URL: כתובת שרת Ollama (המודל המקומי).
   - ANTHROPIC_AUTH_TOKEN: ערך שהשרת מצפה לו. ב-Ollama זה "ollama".
   - ANTHROPIC_DEFAULT_*_MODEL: המודל שנעשה בו שימוש בכל שלוש הרמות.
   - שתי השורות האחרונות מכבות טלמטריה ובטא ניסיוניות.
4. בדיקת חיבור. חייבת להחזיר תשובה מהמודל לפני שממשיכים:
       claude -p "Reply with the single word OK"
   אם זה נכשל: שרת Ollama לא רץ, הכתובת בקובץ ההגדרות שגויה, או שהמודל לא
   נטען. בלי זה כל הבדיקות יסתיימו ב-timeout ולא ילמדו כלום.


חלק ג. הכנת הסקריפט
----------------------------------------------------
1. צור תיקייה, למשל C:\claude-probe
2. פתח את פנקס הרשימות (Notepad), הדבק בו את הקוד שבחלק ט' (בסוף הקובץ; כל מה שבין שני
   הקווים, מהשורה "// probe-standalone.js" ועד הסוף).
3. שמור בשם  probe-standalone.js  בתיקייה הזו. בחלון השמירה:
   - "שמור כסוג" = כל הקבצים (All files), כדי שלא יתווסף .txt
   - קידוד = UTF-8
4. בדיקה שהקובץ תקין (לא אמורה להיות הודעת שגיאה):
       cd C:\claude-probe
       node --check probe-standalone.js
   הקוד כולו ב-ASCII (בלי עברית ובלי תווים מיוחדים), כדי שהקידוד לא יפגע בו.


חלק ד. הרצת הסקריפט
----------------------------------------------------
הפקודה המלאה (שנה את הנתיב ל-claude.exe שלך אם הוא שונה):

    cd C:\claude-probe
    node probe-standalone.js --claude "C:\Users\User\.local\bin\claude.exe" --out probe-report.json

אם claude נמצא ב-PATH אפשר גם:

    node probe-standalone.js --out probe-report.json

כיצד לדעת מה הנתיב: הפקודה  where.exe claude  מדפיסה אותו.

פרמטרים:
  --claude <נתיב>        הקובץ שמריצים. ברירת מחדל: claude
  --out <קובץ>           לאן נכתב הדוח. ברירת מחדל: probe-report.json בתיקייה הנוכחית
  --only p1,p2           מריץ רק בדיקות שהשם שלהן מתחיל כך (ראה חלק ה)
  --turn-timeout <שניות> כמה זמן מחכים לתשובת מודל בכל שלב. ברירת מחדל 180

משך: בין 10 ל-30 דקות עם מודל מקומי, תלוי במהירות. הסקריפט מדפיס שורה לכל בדיקה
(למשל "p3_plain_turn ... done (42s)") ושומר את הדוח אחרי כל בדיקה, כך שאם
אתה עוצר באמצע (Ctrl+C) מה שכבר רץ נשמר.

מומלץ להריץ קודם רק את שתי הבדיקות הקצרות, לראות שהכול עובד, ורק אז הכול:

    node probe-standalone.js --claude "C:\Users\User\.local\bin\claude.exe" --out quick.json --only p1,p2
    node probe-standalone.js --claude "C:\Users\User\.local\bin\claude.exe" --out probe-report.json

מה הסקריפט עושה לך על המחשב:
- יוצר תיקייה זמנית  %TEMP%\claude-probe-XXXXXX  ורץ בתוכה.
- ה-CLI עצמו שומר שיחות בדיקה בתיקיית ההיסטוריה שלו:
      C:\Users\User\.claude\projects\...claude-probe-...
  אחרי שסיימת אפשר למחוק את התיקיות האלה. הן לא קשורות לשום פרויקט שלך.
- בבדיקה p8 מופעלת פקודת /loop. היא נעצרת מיד כשהתהליך נסגר (אחרי כ-25 שניות).
- הסקריפט לא שולט במחשב ולא פותח חיבור החוצה. הוא רק מריץ את claude מקומית.
  כשהמודל מבקש להריץ כלי, הסקריפט מאשר אוטומטית רק:
    * פקודת Bash אחת פשוטה שמתחילה ב-ping, sleep, echo או timeout, בלי אופרטורים
      של shell (& | ; < > ` $ וסוגריים) ובאורך של עד 120 תווים.
    * עריכה (Edit) של הקובץ a.txt בתיקיית ה-temp בלבד.
  כל בקשה אחרת נדחית, והבקשות שנדחו נרשמות בדוח (permissionsAsked).


חלק ה. הסבר מפורט על כל בדיקה
----------------------------------------------------
בכל בדיקה: מה היא עושה, איזו שאלה היא עונה עליה, איך לפרש את התוצאה בדוח,
ואיזה פיצ'ר מושפע. את הפירוש אנחנו נעשה, אתה רק צריך לשלוח את הדוח.
שמות הבדיקות הם המפתחות בדוח תחת "probes".

p1_initialize   (בדיקות 1 ו-2)
  מה: שולח ל-CLI בקשת initialize ורושם מה חזר.
  מה מחפשים:
   - models: רשימת המודלים. האם יש בה שדות מעבר ל-value, displayName, description,
     למשל תמיכה ב-effort, ב-thinking או בראייה. אם יש, נציג את הבורר והמתגים רק כשהם
     רלוונטיים למודל. אם אין, נצטרך לקבוע לפי יכולות המודל ב-Ollama (בדיקה ידנית 1).
   - commands: רשימת פקודות ה-/. האם יש שדה שמבדיל skills מפקודות מובנות. אם אין,
     לא נוכל לחלק את התפריט לקבוצות לפי המידע מה-CLI.
   - agents, account (רק שמות השדות נשמרים, לא הערכים).
  משפיע על: תפריט / מקובץ, בורר מודל, Thinking, Effort, תמונות.

p2_control_requests   (בדיקות 6, 7, 9)
  מה: שולח בקשות בקרה עם נתונים מדומים: rewind_files, mcp_status, stop_task,
  get_context_usage, mcp_reconnect, mcp_toggle. אנחנו לא מצפים להצלחה.
  איך לפרש: שגיאה שמכילה את המילה unknown או unsupported פירושה שהבקשה לא קיימת
  ב-CLI. כל שגיאה אחרת (למשל "message not found" או "missing field") פירושה
  שהבקשה קיימת, והיא רק דחתה את הנתונים המדומים. תגובה מוצלחת פירושה שהיא קיימת
  ועובדת בלי פרמטרים.
  משפיע על: Checkpoints ו-rewind, ניהול MCP מהממשק, עצירת משימות רקע, מד הקשר.

p3_plain_turn   (מד הקשר ושורת שימוש)
  מה: שיחה קצרה אחת ("Reply with the single word OK").
  מה מחפשים: אילו סוגי אירועים מגיעים, איזה usage יש בהודעת העוזר ובתוצאה (קלט,
  פלט, cache), אם יש עלות ומשך, ומה נמצא בהודעת ה-init (מודל, כלים, פקודות).
  משפיע על: מד ההקשר, שורת השימוש בסשן.
  אם הבדיקה הזו נכשלת (timedOut=true) כל מה שאחריה לא יעבוד. עצור ובדוק את שלב 4
  בחלק ב.

p4_message_during_turn   (בדיקה 12 - תור הודעות)
  מה: שולח בקשה ארוכה ("Count from 1 to 40"), ואחרי 4 שניות שולח הודעה שנייה בזמן
  שהמודל עדיין עונה.
  איך לפרש: resultsReceived=2 פירושו שה-CLI מקבל הודעה באמצע תור ומטפל בה אחרי
  הראשונה, כלומר אפשר לבנות תור הודעות. resultsReceived=1 פירושו שההודעה נבלעה או
  מוזגה; אז התור ייבנה בתוסף (נחכה לסיום לפני שליחה). exited=true פירושו
  שהתהליך קרס, וצריך לראות את זה.
  משפיע על: תור הודעות, Ctrl+Enter לשליחה מיידית.

p5_slash_commands   (בדיקות 5 ו-11)
  מה: שולח בזו אחר זו את /context, /status, /config, /theme, /compact,
  /rename probe-rename-marker, /recap, /usage, /hooks, /memory, ורושם לכל אחת אם
  חזרה תשובה, האם הייתה שגיאה, ומה הטקסט.
  מה מחפשים:
   - אילו פקודות עובדות במצב stream-json ואילו חוזרות בשגיאה או נתקעות
     (נתקעת = timedOut=true). אלה שלא עובדות יסומנו בתוסף "זמין בטרמינל בלבד".
   - האם /rename כתב את השם לקובץ ההיסטוריה (jsonl) של ה-CLI: המפתח
     renameMarkerFoundInTranscript. אם true, אפשר לממש שינוי שם דרך ה-CLI. אם false,
     שינוי שם לא יהיה זמין.
  זמן: עד 90 שניות לכל פקודה, עד כ-15 דקות בסך הכול.
  משפיע על: תפריט הפקודות, שינוי שם סשן, מסנני רשימת הסשנים.

p6_updated_input   (בדיקה 4 - אישור עריכה חלקית)
  מה: יוצר קובץ a.txt בתיקיית ה-temp, מבקש מהמודל לערוך אותו בכלי Edit, ובבקשת
  ההרשאה מחליף בכוונה את הטקסט החדש ב-PROBE_CHANGED.
  איך לפרש: updatedInputHonoured=true פירושו שה-CLI מכבד שינוי שהתוסף עושה
  לעריכה, ולכן אפשר לאשר או לדחות בלוק שינוי בנפרד. false פירושו שה-CLI מתעלם,
  ונצטרך לאשר/לדחות עריכה שלמה בלבד.
  שים לב: אם המודל המקומי לא קרא לכלי Edit (permissionsAsked ריק), הבדיקה לא
  חד-משמעית. שלח לנו את הדוח בכל מקרה.
  משפיע על: תצוגת diff ואישור שינויים.

p7_todo_shell_background   (בדיקות 7 ו-12)
  מה: שלושה שלבים. (1) מבקש מהמודל ליצור רשימת TodoWrite. (2) שולח "!echo
  probe-shell-line" כדי לראות אם מצב Shell עם ! עובד. (3) מבקש להריץ פקודה ארוכה
  ברקע ומתעד אילו אירועי משימה/רקע מגיעים (taskLikeMessages).
  משפיע על: רשימת המשימות של Claude, מצב Shell, כפתור "העבר לרקע", מפת משימות.

p8_loop   (בדיקה 10)
  מה: שולח "/loop 1m reply with the word TICK", מחכה 25 שניות ורושם את האירועים.
  מה מחפשים: האם מגיע אירוע מיוחד ל-loop שמאפשר להציג מחוון בצ'אט.
  משפיע על: מחוון /loop.


חלק ו. בדיקות ידניות (לא בסקריפט)
----------------------------------------------------
בדיקה ידנית 1: מה המודל המקומי יודע לעשות (ראייה / חשיבה / כלים)
  מריצים ב-PowerShell (עם הכתובת והמודל שלך):

      Invoke-RestMethod -Method Post -Uri http://172.27.5.5:11436/api/show -ContentType application/json -Body '{"model":"qwen3.8:27b"}' | Select-Object -ExpandProperty capabilities

  אם ollama מותקן אצלך אפשר גם:  ollama show qwen3.8:27b
  התשובה היא רשימה כמו: completion, vision, tools, thinking.
  - אם אין vision: לא נציג הדבקת תמונות.
  - אם אין thinking: לא נציג את מתג Thinking.
  - אם אין tools: ה-CLI לא יוכל לערוך קבצים, וזה חשוב לדעת.
  העתק לנו את הפלט.

בדיקה ידנית 2: חיבור IDE (בדיקות 3 ו-8)
      claude --help | Select-String -Pattern "ide"
      Get-ChildItem "$env:USERPROFILE\.claude\ide" -ErrorAction SilentlyContinue
  ואז פתח VS Code, פתח טרמינל משולב (Ctrl+`), הרץ  claude  ובתוכו  /ide
  והעתק לנו את כל מה שמודפס.
  מטרה: לראות אם ה-CLI תומך בחיבור IDE ומה הוא מצפה לו. התיקייה .claude\ide
  עשויה להיות לא קיימת או ריקה. זה בסדר. זו תוצאה ולא כשל.

בדיקה ידנית 3: הוספה והסרה של שרת MCP (בדיקה 9)
      claude mcp --help
      claude mcp add --help
      claude mcp add probe-test -- node -e "setInterval(()=>{},1000)"
      claude mcp list
      Get-Item "$env:USERPROFILE\.claude.json" | Select-Object LastWriteTime
      claude mcp remove probe-test
      claude mcp list
  מטרה: לבדוק אם אפשר להוסיף ולהסיר שרתים דרך הפקודה claude mcp (הדרך הבטוחה
  שהתוסף ישתמש בה), ואיזה קובץ מתעדכן. אחרי ההסרה ה-list הסופי לא אמור להציג
  את probe-test.

בדיקה ידנית 4: דגלי rewind ו-fork (בדיקה 6)
      claude --help | Select-String -Pattern "fork|resume|rewind|continue"


חלק ז. מה לשלוח חזרה
----------------------------------------------------
1. את הקובץ probe-report.json. מכיוון שהמחשב לא מחובר לגיטהאב, הדרכים הן:
   - להעתיק ללוח ולהדביק בשיחה:
         Get-Content probe-report.json -Raw | Set-Clipboard
   - או לצרף את הקובץ לשיחה.
   אם הדוח גדול מאוד, אפשר לשלוח כל בדיקה בנפרד. הדוח הוא JSON וכל בדיקה היא
   מפתח נפרד.
2. את הפלט של הבדיקות הידניות 1 עד 4.
3. את הגרסאות: node -v ו-claude --version.
4. כל הודעת שגיאה שהופיעה, גם אם הסקריפט המשיך.

לפני שליחה, עבור על הדוח. הסקריפט לא שומר ערכי חשבון, אבל הדוח כולל טקסטים
של תשובות המודל ונתיבי תיקיות.


חלק ח. פתרון בעיות
----------------------------------------------------
- "claude is not recognized" / ENOENT:  תן לדגל --claude את הנתיב המלא. מצא אותו עם
  where.exe claude.
- כל הבדיקות מסתיימות ב-timedOut=true: המודל לא עונה. חזור לחלק ב שלב 4.
- הבדיקה p1 נכשלת עם "initialize timed out": ה-CLI לא עלה. הרץ ידנית
  claude --version וראה שגיאה.
- שגיאת "unknown option" מ-claude: הגרסה ישנה מדי. שלח לנו את הגרסה.
- הרצה איטית מאוד: הגדל  --turn-timeout 300  או הרץ בדיקות בנפרד עם --only.
- רוצה להריץ בדיקה אחת שוב:  --only p5  (שם הדוח ידרוס. תן --out אחר כדי לשמור).
- ניקוי אחרי הבדיקות: מחק את התיקיות  %TEMP%\claude-probe-*  ואת התיקיות
  C:\Users\User\.claude\projects\*claude-probe*


חלק ט. הקוד המלא של הסקריפט
----------------------------------------------------
העתק את כל מה שמתחת לשורה הזו עד סוף הקובץ (כולל השורה הראשונה
"// probe-standalone.js") אל הקובץ probe-standalone.js.
קטע ה-JavaScript מחולק לארבעה חלקים (מסומנים בהערות בתוכו):
  1. spawn: איך מפעילים את claude (כולל קבצי .cmd ב-Windows).

// probe-standalone.js - ONE self-contained file (no other files, no npm needed). Node 18+ (22 recommended).
// Usage: node probe-standalone.js --claude "C:\\path\\claude.exe" --out probe-report.json [--only p1,p2] [--turn-timeout 180]
const fs = require('fs');
const os = require('os');
const path = require('path');
const { spawn } = require('child_process');
const { EventEmitter } = require('events');

// ---------- part 1: how to start the CLI (from src/cli/spawn.js) ----------
// Starts the CLI executable. On Windows a bare name is resolved on PATH x PATHEXT,
// and .cmd/.bat files go through cmd.exe because Node cannot spawn them directly.

const ENTRYPOINT = 'claude-local-vscode';

function resolveExecutable(command, env = process.env, platform = process.platform) {
  if (path.isAbsolute(command) || command.includes('/') || command.includes('\\')) return command;
  const dirs = (env.PATH || env.Path || '').split(path.delimiter).filter(Boolean);
  const exts = platform === 'win32'
    ? (env.PATHEXT || '.COM;.EXE;.BAT;.CMD').split(';').filter(Boolean)
    : [''];
  for (const dir of dirs) {
    for (const ext of platform === 'win32' && path.extname(command) ? [''] : exts) {
      const candidate = path.join(dir, command + ext.toLowerCase());
      if (fs.existsSync(candidate)) return candidate;
    }
  }
  return command;
}

function quoteForCmd(arg) {
  return /[\s"&|<>^()]/.test(arg) ? `"${arg.replace(/"/g, '""')}"` : arg;
}

function spawnCli(claudePath, args, { cwd, env = process.env } = {}) {
  const exe = resolveExecutable(claudePath, env);
  const childEnv = { ...env, CLAUDE_CODE_ENTRYPOINT: ENTRYPOINT };
  const options = { cwd, env: childEnv, stdio: ['pipe', 'pipe', 'pipe'], windowsHide: true };
  if (process.platform === 'win32' && /\.(cmd|bat)$/i.test(exe)) {
    const line = [exe, ...args].map(quoteForCmd).join(' ');
    return spawn(process.env.ComSpec || 'cmd.exe', ['/d', '/s', '/c', `"${line}"`], {
      ...options,
      windowsVerbatimArguments: true,
    });
  }
  return spawn(exe, args, options);
}

// ---------- part 2: CLI arguments (from src/cli/args.js) ----------
// The CLI argument list for one long-lived stream-json conversation process.

const PERMISSION_MODES = ['default', 'acceptEdits', 'plan', 'bypassPermissions'];

// allowBypass: the CLI only accepts a later switch to bypassPermissions when the process was
// started with --allow-dangerously-skip-permissions (checked against CLI 2.1.181).
function buildArgs({ permissionMode = 'default', resume, model, allowBypass = false } = {}) {
  const mode = PERMISSION_MODES.includes(permissionMode) ? permissionMode : 'default';
  const args = [
    '-p',
    '--input-format', 'stream-json',
    '--output-format', 'stream-json',
    '--verbose',
    '--include-partial-messages',
    '--permission-prompt-tool', 'stdio',
    '--permission-mode', mode,
  ];
  if (allowBypass) args.push('--allow-dangerously-skip-permissions');
  if (resume) args.push('--resume', resume);
  if (model) args.push('--model', model);
  return args;
}

// ---------- part 3: the stream-json process wrapper (from src/cli/process.js) ----------
// One CLI conversation process: newline-delimited JSON over stdio plus the control protocol.
// Emits 'message' for every stream line that is not a control frame, 'controlRequest' for
// requests the CLI sends us (can_use_tool), 'stderr', and 'exit'.

const KILL_GRACE_MS = 6000;

class CliProcess extends EventEmitter {
  constructor({ claudePath, args, cwd, env, log = () => {} }) {
    super();
    this.log = log;
    this.pending = new Map();
    this.nextId = 1;
    this.stderrTail = '';
    this.exited = false;
    this.child = spawnCli(claudePath, args, { cwd, env });
    this.child.on('error', (err) => this.finish({ code: null, error: err }));
    this.child.on('exit', (code, signal) => this.finish({ code, signal }));
    this.child.stdin.on('error', () => {});
    this.child.stderr.setEncoding('utf8');
    this.child.stderr.on('data', (d) => {
      this.stderrTail = (this.stderrTail + d).slice(-3000);
      this.emit('stderr', d);
    });
    this.readLines(this.child.stdout, (line) => this.onLine(line));
  }

  readLines(stream, onLine) {
    let buf = '';
    stream.setEncoding('utf8');
    stream.on('data', (chunk) => {
      buf += chunk;
      let i;
      while ((i = buf.indexOf('\n')) >= 0) {
        const line = buf.slice(0, i).trim();
        buf = buf.slice(i + 1);
        if (line) onLine(line);
      }
    });
  }

  onLine(line) {
    this.log(`<< ${line}`);
    let msg;
    try {
      msg = JSON.parse(line);
    } catch {
      this.log(`ignored non-JSON line`);
      return;
    }
    if (msg.type === 'control_response') {
      const { request_id: id, subtype, response, error } = msg.response || {};
      const entry = this.pending.get(id);
      if (!entry) return;
      this.pending.delete(id);
      clearTimeout(entry.timer);
      if (subtype === 'success') entry.resolve(response || {});
      else entry.reject(new Error(error || 'control request failed'));
      return;
    }
    if (msg.type === 'control_request') {
      this.emit('controlRequest', msg.request_id, msg.request || {});
      return;
    }
    if (msg.type === 'control_cancel_request') {
      this.emit('controlCancel', msg.request_id);
      return;
    }
    this.emit('message', msg);
  }

  send(obj) {
    if (this.exited) return false;
    const line = JSON.stringify(obj);
    this.log(`>> ${line}`);
    this.child.stdin.write(line + '\n');
    return true;
  }

  sendUserText(text) {
    return this.send({ type: 'user', message: { role: 'user', content: [{ type: 'text', text }] } });
  }

  request(subtype, payload = {}, timeoutMs = 60000) {
    const requestId = `ext-${this.nextId++}`;
    return new Promise((resolve, reject) => {
      if (this.exited) return reject(new Error('process exited'));
      const timer = setTimeout(() => {
        this.pending.delete(requestId);
        reject(new Error(`${subtype} timed out`));
      }, timeoutMs);
      this.pending.set(requestId, { resolve, reject, timer });
      this.send({ type: 'control_request', request_id: requestId, request: { subtype, ...payload } });
    });
  }

  respond(requestId, response) {
    this.send({ type: 'control_response', response: { subtype: 'success', request_id: requestId, response } });
  }

  respondError(requestId, error) {
    this.send({ type: 'control_response', response: { subtype: 'error', request_id: requestId, error } });
  }

  interrupt() {
    return this.request('interrupt', {}, 10000);
  }

  kill() {
    if (this.exited) return;
    const pid = this.child.pid;
    try { this.child.stdin.end(); } catch {}
    if (process.platform === 'win32' && pid) {
      spawn('taskkill', ['/pid', String(pid), '/T', '/F'], { windowsHide: true }).on('error', () => {});
    } else {
      this.child.kill('SIGTERM');
    }
  }

  // Interrupt first; if the process is still alive after the grace period, kill it.
  stop() {
    const timer = setTimeout(() => this.kill(), KILL_GRACE_MS);
    this.once('exit', () => clearTimeout(timer));
    return this.interrupt().then(() => clearTimeout(timer), () => {});
  }

  finish(info) {
    if (this.exited) return;
    this.exited = true;
    for (const { reject, timer } of this.pending.values()) {
      clearTimeout(timer);
      reject(new Error('process exited'));
    }
    this.pending.clear();
    this.emit('exit', { ...info, stderrTail: this.stderrTail });
  }
}

// ---------- part 4: the probes (from dev/probe-cli.js) ----------
// Dev-only feasibility probe: runs the checks from docs/features-plan.md against a real CLI.
// Usage: node dev/probe-cli.js [--claude <path>] [--out <report.json>] [--only p1,p2] [--turn-timeout <sec>]
// It spawns the CLI with the same arguments the extension uses, in a throw-away folder, and writes
// everything it saw to a JSON report. Nothing here is shipped with the extension.

const argv = process.argv.slice(2);
const opt = (name, fallback) => {
  const i = argv.indexOf(`--${name}`);
  return i >= 0 ? argv[i + 1] : fallback;
};
const claudePath = opt('claude', 'claude');
const outFile = path.resolve(opt('out', 'probe-report.json'));
const only = opt('only', '') ? opt('only').split(',') : null;
const turnTimeoutMs = Number(opt('turn-timeout', '180')) * 1000;

const sandbox = fs.mkdtempSync(path.join(os.tmpdir(), 'claude-probe-'));
const report = { claudePath, sandbox, startedAt: new Date().toISOString(), probes: {} };
const save = () => fs.writeFileSync(outFile, JSON.stringify(report, null, 2));
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// Safety filters for the auto-answered permission requests.
// Bash: only a single harmless command (ping/sleep/echo/timeout) with no shell operators.
const isSafeBash = (cmd) => {
  const c = String(cmd || '').trim().replace(/^!/, '');
  return c.length > 0 && c.length < 120 && /^(ping|sleep|echo|timeout)(\s|$)/i.test(c) && !/[&|;<>`$()\r\n]/.test(c);
};
// Edits: only the probe's own a.txt inside the throw-away folder.
const isProbeFile = (p) => {
  try { return path.resolve(String(p || '')) === path.join(sandbox, 'a.txt') || path.resolve(sandbox, String(p || '')) === path.join(sandbox, 'a.txt'); }
  catch { return false; }
};

// Starts one process; every non-control message is kept in `seen`. Tool permission requests are
// recorded and answered by `onPermission(input request) -> response`.
function start(permissionMode, onPermission) {
  const seen = [];
  const permissions = [];
  const proc = new CliProcess({ claudePath, args: buildArgs({ permissionMode }), cwd: sandbox, env: process.env });
  proc.on('message', (m) => seen.push(m));
  proc.on('controlRequest', (id, req) => {
    permissions.push({ tool: req.tool_name, input: req.input, keys: Object.keys(req) });
    const answer = req.subtype === 'can_use_tool' && onPermission
      ? onPermission(req)
      : { behavior: 'deny', message: 'probe: denied' };
    if (req.subtype === 'can_use_tool') proc.respond(id, answer);
    else proc.respondError(id, 'unsupported in probe');
  });
  return { proc, seen, permissions };
}

// Sends a user message and waits for the next `result` message (or a timeout).
function turn(h, text, timeoutMs = turnTimeoutMs) {
  const from = h.seen.length;
  const sentAt = Date.now();
  h.proc.sendUserText(text);
  return new Promise((resolve) => {
    const tick = setInterval(() => {
      const slice = h.seen.slice(from);
      const result = slice.find((m) => m.type === 'result');
      if (result || Date.now() - sentAt > timeoutMs || h.proc.exited) {
        clearInterval(tick);
        resolve({ timedOut: !result, exited: h.proc.exited, result, messages: slice });
      }
    }, 250);
  });
}

const summarize = (messages) => {
  const types = {};
  for (const m of messages) {
    const key = m.type + (m.subtype ? `/${m.subtype}` : '') + (m.type === 'stream_event' ? `/${m.event && m.event.type}` : '');
    types[key] = (types[key] || 0) + 1;
  }
  const tools = [];
  for (const m of messages) {
    if (m.type === 'assistant' && m.message && Array.isArray(m.message.content)) {
      for (const b of m.message.content) if (b.type === 'tool_use') tools.push(b.name);
    }
  }
  return { eventTypes: types, toolsUsed: tools };
};

const probes = {
  // Checks 1 and 2: what `initialize` returns (models, commands, agents ...).
  async p1_initialize() {
    const h = start('default');
    try {
      const res = await h.proc.request('initialize', {}, 90000);
      return {
        topLevelKeys: Object.keys(res),
        models: res.models,
        commandsCount: (res.commands || []).length,
        commands: res.commands,
        agents: res.agents,
        accountKeys: res.account && Object.keys(res.account), // values left out on purpose
        output_style: res.output_style,
      };
    } finally { h.proc.kill(); }
  },

  // Checks 6, 7, 9: which control-request subtypes exist. "unknown"/"unsupported" in the error
  // text means the CLI has no such request; any other error means it exists but rejected our dummy data.
  async p2_control_requests() {
    const h = start('default');
    try {
      await h.proc.request('initialize', {}, 90000);
      const out = {};
      const tries = [
        ['rewind_files', { user_message_id: 'dummy-id', dry_run: true }],
        ['mcp_status', {}],
        ['stop_task', { task_id: 'dummy' }],
        ['get_context_usage', {}],
        ['mcp_reconnect', { serverName: 'dummy' }],
        ['mcp_toggle', { serverName: 'dummy', enabled: false }],
      ];
      for (const [subtype, payload] of tries) {
        try { out[subtype] = { ok: true, response: await h.proc.request(subtype, payload, 20000) }; }
        catch (e) { out[subtype] = { ok: false, error: String(e.message || e) }; }
      }
      return out;
    } finally { h.proc.kill(); }
  },

  // A plain turn: which events and usage fields arrive (context meter, session usage line).
  async p3_plain_turn() {
    const h = start('default');
    try {
      await h.proc.request('initialize', {}, 90000);
      const t = await turn(h, 'Reply with the single word OK.');
      const assistant = t.messages.filter((m) => m.type === 'assistant').pop();
      return {
        timedOut: t.timedOut,
        ...summarize(t.messages),
        result: t.result,
        lastAssistantUsage: assistant && assistant.message && assistant.message.usage,
        initMessage: h.seen.find((m) => m.type === 'system' && m.subtype === 'init'),
      };
    } finally { h.proc.kill(); }
  },

  // Check 12: a second message while the first turn is still running (message queue).
  async p4_message_during_turn() {
    const h = start('default');
    try {
      await h.proc.request('initialize', {}, 90000);
      h.proc.sendUserText('Count from 1 to 40, one number per line, no other text.');
      await sleep(4000);
      const before = h.seen.length;
      h.proc.sendUserText('After that, reply with the word SECOND.');
      const deadline = Date.now() + turnTimeoutMs;
      while (Date.now() < deadline && h.seen.filter((m) => m.type === 'result').length < 2 && !h.proc.exited) await sleep(500);
      const results = h.seen.filter((m) => m.type === 'result');
      return {
        resultsReceived: results.length,
        resultTexts: results.map((r) => String(r.result || '').slice(0, 120)),
        eventsAfterSecondSend: summarize(h.seen.slice(before)),
        exited: h.proc.exited,
      };
    } finally { h.proc.kill(); }
  },

  // Checks 5, 11: slash commands in stream-json, and whether /rename writes into the transcript.
  async p5_slash_commands() {
    const h = start('default');
    const out = {};
    try {
      await h.proc.request('initialize', {}, 90000);
      await turn(h, 'Reply with the single word OK.');
      for (const cmd of ['/context', '/status', '/config', '/theme', '/compact', '/rename probe-rename-marker', '/recap', '/usage', '/hooks', '/memory']) {
        const t = await turn(h, cmd, 90000);
        out[cmd] = {
          timedOut: t.timedOut,
          resultSubtype: t.result && t.result.subtype,
          isError: t.result && t.result.is_error,
          resultText: String((t.result && t.result.result) || '').slice(0, 300),
          ...summarize(t.messages),
        };
      }
    } finally { h.proc.kill(); }
    await sleep(1000);
    const base = process.env.CLAUDE_CONFIG_DIR || path.join(os.homedir(), '.claude');
    const dir = path.join(base, 'projects', fs.realpathSync(sandbox).replace(/[^a-zA-Z0-9]/g, '-'));
    out.transcriptDir = dir;
    try {
      const files = fs.readdirSync(dir).filter((f) => f.endsWith('.jsonl'));
      out.transcriptFiles = files;
      out.renameMarkerFoundInTranscript = files.some((f) => fs.readFileSync(path.join(dir, f), 'utf8').includes('probe-rename-marker'));
      out.renameLines = files.flatMap((f) => fs.readFileSync(path.join(dir, f), 'utf8').split('\n')
        .filter((l) => l.includes('probe-rename-marker') && !l.includes('"type":"user"')).map((l) => l.slice(0, 300)));
    } catch (e) { out.transcriptError = String(e.message); }
    return out;
  },

  // Check 4: does the CLI honour `updatedInput` from a permission answer (changed edit text)?
  async p6_updated_input() {
    const file = path.join(sandbox, 'a.txt');
    fs.writeFileSync(file, 'one\ntwo\nthree\n');
    const h = start('default', (req) => {
      if (req.tool_name === 'Edit' && isProbeFile(req.input && req.input.file_path)) {
        const input = { ...req.input };
        if ('new_string' in input) input.new_string = 'PROBE_CHANGED';
        return { behavior: 'allow', updatedInput: input };
      }
      return { behavior: 'deny', message: 'probe: denied' };
    });
    try {
      await h.proc.request('initialize', {}, 90000);
      const t = await turn(h, 'Use the Edit tool on a.txt in the current folder: replace the text "two" with "TWO". Do not use any other tool.');
      return {
        timedOut: t.timedOut,
        permissionsAsked: h.permissions,
        fileAfter: fs.readFileSync(file, 'utf8'),
        updatedInputHonoured: fs.readFileSync(file, 'utf8').includes('PROBE_CHANGED'),
        ...summarize(t.messages),
      };
    } finally { h.proc.kill(); }
  },

  // Checks 7, 12: TodoWrite events, `!` shell lines, and background-task events.
  async p7_todo_shell_background() {
    const h = start('default', (req) => {
      if (req.tool_name === 'Bash' && isSafeBash(req.input && req.input.command)) {
        return { behavior: 'allow', updatedInput: req.input };
      }
      return { behavior: 'deny', message: 'probe: denied' };
    });
    const out = {};
    try {
      await h.proc.request('initialize', {}, 90000);
      let t = await turn(h, 'Use the TodoWrite tool to create a todo list with two items: "alpha" and "beta". Then stop.');
      out.todoWrite = summarize(t.messages);
      t = await turn(h, '!echo probe-shell-line', 90000);
      out.bangShell = { timedOut: t.timedOut, resultText: String((t.result && t.result.result) || '').slice(0, 300), ...summarize(t.messages) };
      t = await turn(h, 'Run the command "ping -n 15 127.0.0.1" (or "sleep 15" on Linux/Mac) with the Bash tool using run_in_background true, then tell me it started.', 120000);
      out.background = {
        timedOut: t.timedOut,
        ...summarize(t.messages),
        taskLikeMessages: h.seen.filter((m) => /task|background/i.test((m.subtype || '') + (m.type || ''))).slice(0, 10),
      };
    } finally { h.proc.kill(); }
    return out;
  },

  // Check 10: events while /loop is active.
  async p8_loop() {
    const h = start('default');
    try {
      await h.proc.request('initialize', {}, 90000);
      const from = h.seen.length;
      h.proc.sendUserText('/loop 1m reply with the word TICK');
      await sleep(25000);
      const slice = h.seen.slice(from);
      return { ...summarize(slice), sample: slice.filter((m) => m.type !== 'stream_event').slice(0, 8) };
    } finally { h.proc.kill(); }
  },
};

(async () => {
  const names = Object.keys(probes).filter((n) => !only || only.some((o) => n.startsWith(o)));
  for (const name of names) {
    process.stdout.write(`${name} ... `);
    const t0 = Date.now();
    try {
      report.probes[name] = { ok: true, data: await probes[name]() };
      console.log(`done (${Math.round((Date.now() - t0) / 1000)}s)`);
    } catch (e) {
      report.probes[name] = { ok: false, error: String((e && e.stack) || e) };
      console.log(`FAILED: ${e && e.message}`);
    }
    save();
  }
  report.finishedAt = new Date().toISOString();
  save();
  console.log(`\nReport written to ${outFile}`);
  process.exit(0);
})();
