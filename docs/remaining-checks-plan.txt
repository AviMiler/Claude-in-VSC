תוכנית מלאה: מה שנשאר לבדוק מול ה-CLI ומול התוסף
====================================================
מעודכן ל-1.11.2026, אחרי הרצת הסקריפט הראשון (probe-standalone.js).
הקובץ עומד בפני עצמו: כולל הסברים, פקודות והקוד המלא של הסקריפט השני (probe2).
אין צורך בגיטהאב או באינטרנט.


חלק א. איפה אנחנו
----------------------------------------------------
תוצאות הסקריפט הראשון (גרסת CLI שנמצאה: 2.1.246):

  נענה סופית:
   - פרטי המודלים ב-initialize: יש supportsEffort, supportedEffortLevels,
     supportsAdaptiveThinking, supportsAutoMode. אין שדה ראייה.
   - הבחנה בין skills לפקודות מובנות: הודעת ה-init כוללת skills (19) לעומת
     slash_commands (46), ו-terminal_slash_commands (doctor, color) לפקודות טרמינל.
   - /rename נכתב לקובץ ההיסטוריה (custom-title).
   - אירועי משימות רקע: system/task_started ו-system/background_tasks_changed;
     הבקשה stop_task קיימת.
   - הודעה באמצע תור: מתקבלת ומטופלת אחרי הראשונה (שתי תוצאות).
   - בקשות בקרה שקיימות: rewind_files, mcp_status, mcp_reconnect, mcp_toggle,
     stop_task, get_context_usage.
   - /context, /config, /compact, /rename, /recap, /usage עובדות.
     /status, /theme, /hooks, /memory אינן זמינות ואינן ברשימת הפקודות.
   - אין כלי TodoWrite. הכלים הקיימים: TaskCreate, TaskUpdate, TaskList, TaskGet.
   - /loop הוא skill שמשתמש בכלים CronCreate, CronList, CronDelete.
   - דגלים בשורת הפקודה: --fork-session, --resume, --continue, --ide.

  נשאר פתוח (זה מה שהקובץ הזה מכסה):
   - rewind: הבקשה קיימת אבל החזירה "File rewinding is not enabled".
   - updatedInput: הבדיקה לא הייתה חד-משמעית (לא נשלחה בקשת הרשאה).
   - מצב Auto, צורת בקשות ההרשאה, ראייה, חשיבה ו-Effort בפועל.
   - מצב ה-MCP לאורך זמן, והוספה/הסרה של שרת MCP.
   - /loop, עצירה (interrupt), המשך שיחה (resume) ופיצול (fork).
   - מצב Shell עם ! (נראה כעובד, צריך אישור).
   - שרת IDE.
   - רשימת המודלים של השרת (תוצאת GET /models: ממתינה, תגיע ממך).
   - מה העטיפה claude.cmd עושה, ומה החלון האמיתי של המודל.
   - בדיקת התוסף עצמו בתוך VS Code.


חלק ב. רשימת כל הבדיקות שנשארו
----------------------------------------------------
לכל בדיקה: מספר (R), מה בודקים, למה (אילו פיצ'רים תלויים), איך, ומה עושים לפי התוצאה.
"ידני" = פקודות בחלק ד. "סקריפט" = בדיקה בסקריפט probe2 (חלק ה).

R1. רשימת המודלים של השרת (GET /models)               [ידני M1]  [ממתין לתוצאה שלך]
  מה: מה השרת מחזיר ב-GET על /models. אצלך POST החזיר Method Not Allowed, כלומר
       הכתובת קיימת.
  למה: ייתכן שיש שם גם יכולות המודל (ראייה/חשיבה/חלון הקשר). תלויים: בורר המודל,
       הצגת תמונות, מתג Thinking, מד הקשר.
  פירוש: אם יש שדות יכולות, נשתמש בהם. אם יש רק שמות, נבדוק יכולות בבדיקות R8 ו-R9.

R2. מה העטיפה claude.cmd עושה ואילו משתני סביבה מוגדרים      [ידני M2, M3]
  מה: התוכן של C:\Users\206861775\AppData\Local\Programs\ClaudeCode\claude.cmd
       ושמות משתני הסביבה של ANTHROPIC ו-CLAUDE.
  למה: העטיפה מציגה תפריט בחירת מודל לפני כל הרצה. התוסף חייב לדעת איך המודל נבחר
       כדי להפעיל את claude-bin.exe ישירות. תלויים: claudePath, בורר המודל, environmentVariables.
  פירוש: אם העטיפה רק קובעת משתני סביבה לפי המודל שנבחר, התוסף יוכל להגדיר אותם בעצמו
       ולהציג את אותה רשימה בבורר המודל. חשוב לבדוק את הקובץ לפני שליחה: אם יש בו
       מפתחות או סיסמאות, למחוק אותם.

R3. החלון האמיתי של המודל והסיומת [1m]                       [ידני M3, M8]
  מה: ה-CLI מדווח על חלון הקשר של מיליון טוקנים (המודל נקרא qwen3.8:27b[1m]).
       מה גודל החלון בפועל ב-Ollama (num_ctx)?
  למה: מד ההקשר ו-/compact. אם החלון בפועל קטן בהרבה (למשל 32 אלף), מד שמבוסס על
       מיליון יציג תמיד 0% וידווח שקר.
  פירוש: אם נדע את הגודל האמיתי, נציג אותו; אם לא, נציג טוקנים בלבד בלי אחוזים.

R4. rewind של קבצים (Checkpoints)                            [סקריפט q1, ידני M7]
  מה: הבקשה rewind_files קיימת אבל כבויה ("not enabled"). הסקריפט מפעיל את
       מנגנון השמירה בדרך שבה ה-SDK של Claude עושה זאת (משתנה סביבה
       CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=1 בתהליך בלבד, והדגל
       --replay-user-messages שמחזיר את מזהה ההודעה), עורך קובץ, ואז מחזיר אותו.
  למה: כפתור "חזור לאחור" על הודעות (Checkpoints). אם לא עובד, יישאר רק fork.
  פירוש: fileRestored=true פירושו שהכול עובד כך. אם canRewind נשאר false, נבדוק
       את האפשרות הידנית M7 (הגדרה checkpoints=true דרך /config) אחרי שתשלח לי את
       הדוח, כי היא משנה הגדרה קבועה אצלך.
  הערה: ההנחה לגבי המשתנה והדגל לקוחה מהתיעוד של ה-SDK ולא אומתה על הגרסה שלך.

R5. האם ה-CLI מכבד שינוי של עריכה (updatedInput)             [סקריפט q2]
  מה: חוזרים על בדיקה p6, הפעם עם הוראה לקרוא את הקובץ לפני העריכה (ללא קריאה
       קודמת Edit נכשל לפני שנשלחת בקשת הרשאה). בבקשת ההרשאה מחליפים את הטקסט
       החדש ב-PROBE_CHANGED ובודקים אם הוא נכנס לקובץ.
  למה: אישור/דחייה של בלוק שינוי בנפרד בתצוגת diff (שלב 3 בתוכנית).
  פירוש: updatedInputHonoured=true: אפשר לאשר חלקית. false: נאשר/נדחה עריכה שלמה.
       אם גם הפעם permissionRequests ריק, המודל לא הצליח לבצע את העריכה ונחשוב על
       דרך אחרת לבדוק.

R6. צורת בקשות ההרשאה והתשובות                              [סקריפט q3]
  מה: הבקשה can_use_tool בפועל: אילו שדות יש בה (שם כלי, input, tool_use_id,
       permission_suggestions...), איך נראות ההצעות ל"אשר תמיד", מה קורה כשדוחים
       עם הודעה, איך עובדת שאלה מהמודל (AskUserQuestion) ואיך נראית בקשת אישור תוכנית
       (ExitPlanMode).
  למה: כרטיסי ההרשאה, "אשר תמיד", כרטיס השאלות וכרטיס התוכנית. כרגע הם נבנו מול
       CLI מדומה בלבד. זה אחד הדברים שה-spec מגדיר "לא אומת".
  פירוש: נשווה את השדות האמיתיים למה שהתוסף מצפה, ונתקן אם יש הבדלים.

R7. מצבי הרשאות בזמן ריצה, כולל Auto                       [סקריפט q4]
  מה: שולחים set_permission_mode לכל מצב (acceptEdits, plan, default, auto, dontAsk,
       bypassPermissions) ורושמים מה התקבל.
  למה: בורר המצבים, הוספת מצב Auto (שלב 2). bypassPermissions צפוי להיכשל (דורש דגל
       בהפעלה).
  פירוש: ok=true למצב auto פירושו שאפשר להציע אותו; אם נדחה, לא נציג אותו.

R8. ראייה (תמונות)                                         [סקריפט q5]
  מה: שולחים תמונה קטנה (64x64: חצי שמאלי אדום, חצי ימני כחול) ושואלים מה הצבעים.
  למה: הדבקת תמונות בתיבה (שלב 2). הוחלט להציג רק אם המודל תומך.
  פירוש: looksCorrect=true: המודל רואה. false: אין ראייה (או שה-CLI מסנן תמונות),
       ונסתיר את ההדבקה. אם התשובה ריקה או שיש שגיאה, נעיין בדוח.

R9. חשיבה ו-Effort בפועל                                    [סקריפט q6, ידני M4]
  מה: שואלים שאלת חישוב שלוש פעמים: ברירת מחדל, אחרי /effort high ואחרי /effort low,
       ובודקים אם נוצרים בלוקי thinking, כמה טוקני חשיבה, וכמה זמן.
  למה: מתג Thinking ושורת Effort בבורר המודל. הוחלט להציג רק אם רלוונטי; ה-CLI
       מדווח על תמיכה אצל כל מודל, אבל זה גנרי ולא מוכיח שהמודל המקומי מגיב.
  פירוש: אם אין בלוקי thinking ואין הבדל בין high ל-low, לא נציג את הבקרים.

R10. MCP: מצב לאורך זמן, חיבור מחדש, הפעלה/כיבוי             [סקריפט q7, ידני M5]
  מה: mcp_status בתחילה ואחרי 15 שניות, ואז mcp_reconnect, mcp_toggle (כיבוי והפעלה
       מחדש) על השרת הראשון שלך (db-meta). בסוף השרת מוחזר למצב המקורי.
  למה: דיאלוג ניהול MCP (שלב 5). בדוח הראשון המצב היה pending.
  בנוסף הוספה והסרה: בבדיקה הקודמת הפקודה claude mcp add לא הדפיסה כלום והשרת לא
       נרשם. כנראה בגלל התו > שבתוך הביטוי => שהועבר דרך claude.cmd. חוזרים עם פקודה
       פשוטה (M5), ובודקים אם נוצר בטעות קובץ בשם {},1000)  בתיקייה הנוכחית.
  פירוש: אם add/remove עובדים דרך הפקודה, נשתמש בה בתוסף במקום לערוך קבצי הגדרות.

R11. /loop                                                 [סקריפט q8]
  מה: שולחים /loop 1m ... ומחכים עד שתי דקות וחצי לתשובה הראשונה ועוד דקה וחצי לריצה
       שנייה. רושמים אילו כלים ואירועים עוברים (CronCreate וכו').
  למה: מחוון /loop בצ'אט (שלב 7). בבדיקה הראשונה המודל עוד לא ענה כשהסתיימה ההמתנה.
  פירוש: אם נראים CronCreate/CronDelete או אירוע ייעודי, נבסס עליהם את המחוון.

R12. עצירה (interrupt), המשך שיחה (resume) ופיצול (fork)    [סקריפט q9]
  מה: מבקשים מהמודל לספור עד 300, שולחים interrupt אחרי 8 שניות ורושמים תוך כמה זמן
       מגיעה תוצאה ומה הסוג שלה. אחר כך פותחים תהליך חדש עם --resume ושואלים מה
       המילה שהתבקש לזכור, ועוד פעם עם --resume --fork-session.
  למה: כפתור העצירה, "שיחות קודמות" (resume) ו-fork ב-Checkpoints. ה-spec מגדיר את
       התנהגות ה-interrupt וה-resume כ"לא אומתו".
  פירוש: נכוון את הטיפול בעצירה (כיום ממתינים 4 שניות ואז סוגרים מקומית).

R13. מצב Shell עם !                                         [סקריפט q10]
  מה: שולחים !echo probe-bang-777 ורושמים אם ה-CLI טיפל בזה ישירות או דרך המודל.
  למה: מצב Shell בתיבה (שלב 8). בבדיקה הראשונה נראה שעבד.
  פירוש: אם הוא מטופל כפקודה מקומית, נממש. אם עובר דרך המודל, נחליט אם לשמור.

R14. שרת IDE (הקשר אוטומטי מהעורך, getDiagnostics)        [תלוי בי]
  מה: ב-/ide נאמר "No available IDEs detected", והתיקייה .claude\ide לא קיימת.
       אין לנו דרך לדעת את פורמט קובץ הנעילה והפרוטוקול בלי לבדוק מול ה-CLI.
  מה אעשה אני: אבנה אב-טיפוס קטן (שרת WebSocket ב-Node בלי חבילות) ואכתוב קובץ נעילה
       ב-.claude\ide לפי הידוע לי, ואתן לך פקודות להריץ אותו ולבדוק ב-/ide אם ה-CLI
       מזהה. זה ייעשה אחרי שנסיים את שאר הבדיקות; בינתיים אין לך מה להריץ.
  אופציונלי ושימושי: אם יש לך אי פעם מחשב עם התוסף הרשמי של Claude Code, העתק
       קובץ אחד מהתיקייה %USERPROFILE%\.claude\ide\ (קבצי .lock). הוא יראה את
       הפורמט המדויק. (בסביבה הנוכחית אין התוסף ולכן אין קבצים.)
  למה: הקשר אוטומטי, getDiagnostics. אם נכשל, יש חלופה (צ'יפים מעל התיבה).

R15. בדיקת התוסף עצמו בתוך VS Code                          [ידני M6, M9]
  מה: גרסת VS Code, האם התוסף נטען, וכל רשימת הבדיקות הידנית של ה-spec.
  למה: ה-spec מציין שלא בוצעה בדיקה בתוך VS Code, ושה-CSP של ה-webview, טקסט עברית
       ואנגלית מעורב, וערכות נושא לא נבדקו. בנוסף SETUP.md מציין שבגרסה 1.91.1 התוסף
       לא נטען לפני שהורדנו את הדרישה ל-1.91 ולא נבדק אחרי השינוי.
  פירוש: כל כשל כאן יתוקן לפני שמוסיפים פיצ'רים חדשים.

חלק ד. הפקודות הידניות (PowerShell)
----------------------------------------------------
הכנה: מגדירים משתנה עם הנתיב לקובץ האמיתי (לא לעטיפה, כדי שלא יופיע תפריט בחירת מודל):

    $claude = "C:\Users\206861775\AppData\Local\Programs\ClaudeCode\claude-bin.exe"

M1. רשימת מודלים בשרת (GET, לא POST):

    Invoke-RestMethod http://172.27.5.5:11436/models | ConvertTo-Json -Depth 6
    Invoke-RestMethod http://172.27.5.5:11436/v1/models | ConvertTo-Json -Depth 6

  (אם אחת מהן נכשלת, שלח לי גם את השגיאה.)

M2. תוכן העטיפה. לפני שליחה לבדוק שאין בו מפתחות או סיסמאות ולמחוק אותם:

    Get-Content "C:\Users\206861775\AppData\Local\Programs\ClaudeCode\claude.cmd"

M3. משתני סביבה ממשפחת ANTHROPIC ו-CLAUDE. שמות בלבד, ואחר כך שני ערכים לא רגישים:

    Get-ChildItem Env: | Where-Object { $_.Name -like 'ANTHROPIC*' -or $_.Name -like 'CLAUDE*' } | Select-Object -ExpandProperty Name
    $env:ANTHROPIC_MODEL
    $env:ANTHROPIC_BASE_URL
    Get-Content "$env:USERPROFILE\.claude\settings.json"

  בקובץ settings.json להסתיר ערכי token אם יש (לא חובה, כרגע זה "ollama").

M4. גרסה ודגלים רלוונטיים של ה-CLI:

    & $claude --version
    & $claude --help | Select-String -Pattern "effort|thinking|checkpoint|replay|permission-mode|ide|model"

M5. הוספה והסרה של שרת MCP בצורה בטוחה (בלי תווים מיוחדים):

    Get-ChildItem -Force | Where-Object { $_.Name -like '*1000*' }
    & $claude mcp add probe-test -- node --version
    & $claude mcp list
    & $claude mcp remove probe-test
    & $claude mcp list

  השורה הראשונה בודקת אם נוצר קובץ זר בגלל הפקודה הקודמת. אם נמצא קובץ בשם
  {},1000)  אפשר למחוק אותו (Remove-Item -LiteralPath ...).
  הצפוי: add מדפיס אישור, list מציג את probe-test (ייתכן שמסומן כנכשל כי node --version
  נגמר מיד, וזה בסדר), remove מוחק, list אחרון מציג רק db-meta.

M6. גרסת VS Code:

    code --version

// ---------- part 1: how to start the CLI (from src/cli/spawn.js) ----------
// Starts the CLI executable. On Windows a bare name is resolved on PATH x PATHEXT,
// and .cmd/.bat files go through cmd.exe because Node cannot spawn them directly.

const ENTRYPOINT = 'claude-local-vscode';

function resolveExecutable(command, env = process.env, platform = process.platform) {
  if (path.isAbsolute(command) || command.includes('/') || command.includes('\\')) return command;
  const dirs = (env.PATH || env.Path || '').split(path.delimiter).filter(Boolean);
  const exts = platform === 'win32'
    ? (env.PATHEXT || '.COM;.EXE;.BAT;.CMD').split(';').filter(Boolean)
    : [''];
  for (const dir of dirs) {
    for (const ext of platform === 'win32' && path.extname(command) ? [''] : exts) {
      const candidate = path.join(dir, command + ext.toLowerCase());
      if (fs.existsSync(candidate)) return candidate;
    }
  }
  return command;
}

function quoteForCmd(arg) {
  return /[\s"&|<>^()]/.test(arg) ? `"${arg.replace(/"/g, '""')}"` : arg;
}

function spawnCli(claudePath, args, { cwd, env = process.env } = {}) {
  const exe = resolveExecutable(claudePath, env);
  const childEnv = { ...env, CLAUDE_CODE_ENTRYPOINT: ENTRYPOINT };
  const options = { cwd, env: childEnv, stdio: ['pipe', 'pipe', 'pipe'], windowsHide: true };
  if (process.platform === 'win32' && /\.(cmd|bat)$/i.test(exe)) {
    const line = [exe, ...args].map(quoteForCmd).join(' ');
    return spawn(process.env.ComSpec || 'cmd.exe', ['/d', '/s', '/c', `"${line}"`], {
      ...options,
      windowsVerbatimArguments: true,
    });
  }
  return spawn(exe, args, options);
}

const PERMISSION_MODES = ['default', 'acceptEdits', 'plan', 'bypassPermissions'];

// allowBypass: the CLI only accepts a later switch to bypassPermissions when the process was

// ---------- part 3: the stream-json process wrapper (from src/cli/process.js) ----------
// One CLI conversation process: newline-delimited JSON over stdio plus the control protocol.
// Emits 'message' for every stream line that is not a control frame, 'controlRequest' for
// requests the CLI sends us (can_use_tool), 'stderr', and 'exit'.

const KILL_GRACE_MS = 6000;

class CliProcess extends EventEmitter {
  constructor({ claudePath, args, cwd, env, log = () => {} }) {
    super();
    this.log = log;
    this.pending = new Map();
    this.nextId = 1;
    this.stderrTail = '';
    this.exited = false;
    this.child = spawnCli(claudePath, args, { cwd, env });
    this.child.on('error', (err) => this.finish({ code: null, error: err }));
    this.child.on('exit', (code, signal) => this.finish({ code, signal }));
    this.child.stdin.on('error', () => {});
    this.child.stderr.setEncoding('utf8');
    this.child.stderr.on('data', (d) => {
      this.stderrTail = (this.stderrTail + d).slice(-3000);
      this.emit('stderr', d);
    });
    this.readLines(this.child.stdout, (line) => this.onLine(line));
  }

  readLines(stream, onLine) {
    let buf = '';
    stream.setEncoding('utf8');
    stream.on('data', (chunk) => {
      buf += chunk;
      let i;
      while ((i = buf.indexOf('\n')) >= 0) {
        const line = buf.slice(0, i).trim();
        buf = buf.slice(i + 1);
        if (line) onLine(line);
      }
    });
  }

  onLine(line) {
    this.log(`<< ${line}`);
    let msg;
    try {
      msg = JSON.parse(line);
    } catch {
      this.log(`ignored non-JSON line`);
      return;
    }
    if (msg.type === 'control_response') {
      const { request_id: id, subtype, response, error } = msg.response || {};
      const entry = this.pending.get(id);
      if (!entry) return;
      this.pending.delete(id);
      clearTimeout(entry.timer);
      if (subtype === 'success') entry.resolve(response || {});
      else entry.reject(new Error(error || 'control request failed'));
      return;
    }
    if (msg.type === 'control_request') {
      this.emit('controlRequest', msg.request_id, msg.request || {});
      return;
    }
    if (msg.type === 'control_cancel_request') {
      this.emit('controlCancel', msg.request_id);
      return;
    }
    this.emit('message', msg);
  }

  send(obj) {
    if (this.exited) return false;
    const line = JSON.stringify(obj);
    this.log(`>> ${line}`);
    this.child.stdin.write(line + '\n');
    return true;
  }

  sendUserText(text) {
    return this.send({ type: 'user', message: { role: 'user', content: [{ type: 'text', text }] } });
  }

  request(subtype, payload = {}, timeoutMs = 60000) {
    const requestId = `ext-${this.nextId++}`;
    return new Promise((resolve, reject) => {
      if (this.exited) return reject(new Error('process exited'));
      const timer = setTimeout(() => {
        this.pending.delete(requestId);
        reject(new Error(`${subtype} timed out`));
      }, timeoutMs);
      this.pending.set(requestId, { resolve, reject, timer });
      this.send({ type: 'control_request', request_id: requestId, request: { subtype, ...payload } });
    });
  }

  respond(requestId, response) {
    this.send({ type: 'control_response', response: { subtype: 'success', request_id: requestId, response } });
  }

  respondError(requestId, error) {
    this.send({ type: 'control_response', response: { subtype: 'error', request_id: requestId, error } });
  }

  interrupt() {
    return this.request('interrupt', {}, 10000);
  }

  kill() {
    if (this.exited) return;
    const pid = this.child.pid;
    try { this.child.stdin.end(); } catch {}
    if (process.platform === 'win32' && pid) {
      spawn('taskkill', ['/pid', String(pid), '/T', '/F'], { windowsHide: true }).on('error', () => {});
    } else {
      this.child.kill('SIGTERM');
    }
  }

  // Interrupt first; if the process is still alive after the grace period, kill it.
  stop() {
    const timer = setTimeout(() => this.kill(), KILL_GRACE_MS);
    this.once('exit', () => clearTimeout(timer));
    return this.interrupt().then(() => clearTimeout(timer), () => {});
  }

  finish(info) {
    if (this.exited) return;
    this.exited = true;
    for (const { reject, timer } of this.pending.values()) {
      clearTimeout(timer);
      reject(new Error('process exited'));
    }
    this.pending.clear();
    this.emit('exit', { ...info, stderrTail: this.stderrTail });
  }
}

// Sends one user message (text or content blocks) and waits for the next `result`.
function turn(h, content, timeoutMs = turnTimeoutMs) {
  const from = h.seen.length;
  const sentAt = Date.now();
  const blocks = Array.isArray(content) ? content : [{ type: 'text', text: content }];
  h.proc.send({ type: 'user', message: { role: 'user', content: blocks } });
  return new Promise((resolve) => {
    const tick = setInterval(() => {
      const slice = h.seen.slice(from);
      const result = slice.find((m) => m.type === 'result');
      if (result || Date.now() - sentAt > (quick ? 6000 : timeoutMs) || h.proc.exited) {
        clearInterval(tick);
        resolve({ timedOut: !result, exited: h.proc.exited, result, messages: slice });
      }
    }, 250);
  });
}

  // R6: exact shape of permission requests and of our answers (allow, deny, question, plan).
  async q3_permission_shapes() {
    const out = {};
    const handler = (req) => {
      if (req.tool_name === 'Bash' && answers.mode === 'allow' && isSafeBash(req.input && req.input.command)) {
        return { behavior: 'allow', updatedInput: req.input };
      }
      if (req.tool_name === 'Bash') return { behavior: 'deny', message: 'probe-denied-reason: not allowed in this test' };
      if (req.tool_name === 'AskUserQuestion') {
        const picked = {};
        for (const q of (req.input && req.input.questions) || []) picked[q.question] = (q.options && q.options[0] && q.options[0].label) || 'x';
        return { behavior: 'allow', updatedInput: { ...req.input, answers: picked } };
      }
      if (req.tool_name === 'ExitPlanMode') return { behavior: 'allow', updatedInput: req.input };
      return { behavior: 'deny', message: 'probe: denied' };
    };
    let h = start({ onPermission: handler });
    try {
      await init(h);
      answers.mode = 'allow';
      let t = await turn(h, 'Run exactly this command with the Bash tool: echo shape-test');
      out.bashAllow = {
        timedOut: t.timedOut,
        permissions: h.permissions.map((p) => ({ tool: p.tool, requestKeys: Object.keys(p.request), suggestions: clip(p.request.permission_suggestions, 500), input: clip(p.input, 200) })),
        resultText: resultText(t),
      };
      answers.mode = 'deny';
      const before = h.permissions.length;
      t = await turn(h, 'Now run exactly this command with the Bash tool: echo second-test. If it is refused, quote the refusal reason.');
      out.bashDeny = { timedOut: t.timedOut, newPermissions: h.permissions.length - before, resultText: resultText(t) };
      answers.mode = 'allow';
      const before2 = h.permissions.length;
      t = await turn(h, 'Use the AskUserQuestion tool to ask me which color I prefer (options: red, blue). Then tell me which answer you received.');
      out.askUserQuestion = {
        timedOut: t.timedOut,
        requests: h.permissions.slice(before2).map((p) => ({ tool: p.tool, input: clip(p.input, 600) })),
        resultText: resultText(t),
      };
    } finally { h.proc.kill(); }
    h = start({ mode: 'plan', onPermission: handler });
    try {
      await init(h);
      const t = await turn(h, 'Make a short plan for creating a file hello.txt that contains the word hi, then present the plan for approval.');
      out.planMode = {
        timedOut: t.timedOut,
        requests: h.permissions.map((p) => ({ tool: p.tool, requestKeys: Object.keys(p.request), input: clip(p.input, 600) })),
        resultText: resultText(t),
        ...summarize(t.messages),
      };
    } finally { h.proc.kill(); }
    return out;
  },

  async q8_loop() {
    const h = start({ onPermission: (req) => (/^(CronCreate|CronList|CronDelete|ScheduleWakeup)$/.test(req.tool_name) || (req.tool_name === 'Bash' && isSafeBash(req.input && req.input.command)) ? { behavior: 'allow', updatedInput: req.input } : { behavior: 'deny', message: 'probe: denied' }) });

  // R12: interrupt, resume and fork.
  async q9_interrupt_resume() {
    const out = {};
    let h = start();
    let sessionId;
    try {
      await init(h);
      await turn(h, 'Remember this word: pineapple. Reply with OK.');
      sessionId = sessionIdOf(h);
      out.sessionId = sessionId;
      const from = h.seen.length;
      h.proc.sendUserText('Count slowly from 1 to 300, one number per line, no other text.');
      await sleep(8000);
      const t0 = Date.now();
      out.interruptRequest = await tryReq(h, 'interrupt', {}, 15000);
      while (Date.now() - t0 < (quick ? 1000 : 25000) && !h.seen.slice(from).some((m) => m.type === 'result') && !h.proc.exited) await sleep(500);
      const res = h.seen.slice(from).find((m) => m.type === 'result');
      out.afterInterrupt = { msToResult: res ? Date.now() - t0 : null, resultSubtype: res && res.subtype, isError: res && res.is_error, terminalReason: res && res.terminal_reason, processExited: h.proc.exited };
      if (!h.proc.exited) {
        const t = await turn(h, 'Reply with the word ALIVE.', 90000);
        out.aliveAfterInterrupt = { timedOut: t.timedOut, text: resultText(t) };
      }
    } finally { h.proc.kill(); }
    if (!sessionId) return out;
    await sleep(2000);
    h = start({ resume: sessionId });
    try {
      await init(h);
      const t = await turn(h, 'What word did I ask you to remember? Answer with just the word.');
      out.resume = { timedOut: t.timedOut, answer: resultText(t), sessionIdAfterResume: sessionIdOf(h) };
    } finally { h.proc.kill(); }
    await sleep(2000);
    h = start({ resume: sessionId, fork: true });
    try {
      await init(h);
      const t = await turn(h, 'What word did I ask you to remember? Answer with just the word.');
      const newId = sessionIdOf(h);
      out.fork = { timedOut: t.timedOut, answer: resultText(t), newSessionId: newId, differsFromOriginal: !!newId && newId !== sessionId };
    } finally { h.proc.kill(); }
    return out;
  },
