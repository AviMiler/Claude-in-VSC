# תוכנית עבודה – פיצ'רים של Claude Code ב-VS Code

מקור: `docs/claude-code-vscode-guide-he.html` (24 סעיפים). מגבלות הפרויקט שמשפיעות על כל החלטה (מתוך `spec.md`):

- מכונה offline בסופו של דבר: אין רשת, CDN, פיצ'רי ענן.
- התוסף לא שומר כלום (אין globalState/workspaceState/קבצים). ה-CLI הוא מקור האמת; היסטוריה נקראת מה-transcripts בלבד.
- JS רגיל, בלי build ובלי npm. כל מחרוזת למשתמש בעברית.

**כללי עבודה:** כל העבודה והמיזוגים ב-ענף `develop` בלבד. רשימת הפקודות לבדיקות מול ה-CLI: `docs/cli-checks.md` (הסקריפט: `dev/probe-cli.js`).

## החלטות
מתעדכן אחרי כל שלב.

### שלב 1 – פתיחה, הפעלה ומיקום (הוחלט)
- נקודות כניסה: להוסיף **Open in Terminal** ואייקון **Activity Bar לרשימת סשנים** (תלוי בשלב 4). **Open in New Window** – לא.
- התחברות: אין login (מודל מקומי). **כרטיס בעברית בצ'אט כשה-CLI נכשל** (שגיאת חיבור/לא מחובר): בדיקת ANTHROPIC_BASE_URL ב-`~/.claude/settings.json`, שהשרת המקומי רץ, ו-`claudeLocal.claudePath`, עם כפתור שפותח את settings.json. בלי צ'קליסט היכרות.
- קישורי URI: **ליישם** `vscode://local.claude-local/open` (פרמטרים prompt, session) **עם אישור לפני שליחה**. טקסט נכנס לתיבה, לא נשלח אוטומטית.
- מיקום: **להוסיף שתי הגדרות** – `claudeLocal.preferredLocation` (panel/sidebar) ו-`claudeLocal.lockEditorGroups`.

### שלב 2 – תיבת הפרומפט (הוחלט)
- מצבי הרשאות: להוסיף **מצב Auto** (אם ה-CLI דוחה – הודעה והמצב לא משתנה) ולוודא ש-**/plan ו-/plan open** מופיעים ומעדכנים את הבורר.
- Plan כמסמך: **גרסה ב** – כפתור "פתח בעורך" בכרטיס התוכנית, מסמך Markdown וירטואלי לקריאה בלבד (`TextDocumentContentProvider`, בלי כתיבת קובץ). בלי הערות בשורות; תגובות בתיבה.
- תפריט `/`: **קבוצות + הבחנה בין skills לפקודות מובנות** (לפי נתוני initialize; לבדוק מה ה-CLI מחזיר).
- @-mentions: **קבצים ותיקיות בלבד** (בלי @terminal ובלי @browser).
- תמונות/קבצים: **הדבקת תמונות, גרירת קבצים (Shift), PDF ו-LaTeX** (KaTeX vendored; PDF – ה-CLI קורא, דורש poppler).
  - דרישת המשתמש: אם המודל לא תומך ראייה, להסתיר/לנטרל את הדבקת התמונות.
- בורר מודל: **מתג Thinking + שורת Effort**, עם דרישה: **להציג רק אם רלוונטי** למודל (לבדוק בתשובת initialize אם יש שדות תמיכה; אם אין דרך לדעת – לבדוק התנהגות מול ה-CLI האמיתי לפני יישום). Ultracode – לא.
- כלי עזר: **כפתור העתקה לכל תשובה** + **פאנל /btw** (שאלת צד בלי כלים ובלי להיכנס להיסטוריה). בלי סימניות.
- מחוונים: **מד הקשר + כפתור /compact** ו-**מפת סוכנים** (תלוי בשלב 4). בלי שעון קאש.

### שלב 3 – הקשר מהעורך ו-diff (הוחלט, עם בדיקות מקדימות)
- הקשר אוטומטי (בחירה + קובץ פתוח): **קודם לנסות דרך שרת IDE** (משולב עם שלב 5). אם לא עובד מול ה-CLI האמיתי – **נפילה לחלופה בלי שרת**: צ'יפים מעל התיבה (`קובץ: app.ts`, `שורות 5–10`, אפשר להסיר) והתוסף מוסיף שורת הקשר להודעה בשליחה.
- Alt+K: **כן** (מכניס `@path#שורות` לתיבה הפעילה; תלוי ב-@-mentions משלב 2).
- הגדרות: **`attachSelection`, `attachOpenFile`, `respectGitIgnore`** (כולן ברירת מחדל פעילה).
- diff על עריכות: **קודם לנסות אישור לכל בלוק שינוי בנפרד** (CodeLens אשר/דחה, חזרה ל-CLI כ-`updatedInput`). **בדיקה נדרשת**: האם ה-CLI האמיתי מקבל עריכה חלקית. אם לא – נפילה ל-**diff צד-לצד עם אישור/דחייה של הכל** (`vscode.diff` על מסמך וירטואלי).
- autosave: **להוסיף**, ברירת מחדל פעילה (שמירת העורך אחרי עריכה של Claude).

#### בדיקות שחובה לבצע מול ה-CLI האמיתי לפני יישום (מצטבר)
1. האם `models[]` ב-initialize מכיל שדות על תמיכה ב-effort/thinking/ראייה (שלב 2).
2. אילו שדות `commands[]` מחזיר כדי להבדיל skills מפקודות מובנות (שלב 2).
3. האם שרת IDE (lock file ב-`~/.claude/ide/`) מקבל את הקשר הבחירה מול CLI 2.1.181 (שלב 3).
4. האם `can_use_tool` מקבל `updatedInput` עם עריכה חלקית (שלב 3).

### שלב 4 – סשנים, היסטוריה, Checkpoints, רקע (הוחלט)
- ניהול סשנים: **שינוי שם דרך ה-CLI** (/rename בסשן פתוח; לבדוק שה-CLI כותב כך לקובץ) + **מסננים** (פעיל / ממתין לקלט / הסתיים; זמניים, בלי שמירה). **בלי ארכוב ובלי קבוצות** (נבחר "לא לארכב"; כלל "אין שמירה" נשמר).
- פתיחה מחדש: **Ctrl+Shift+T** (רשימת סשנים סגורים בזיכרון בלבד), **נקודות צבע בלשוניות** (כחול = ממתין להרשאה, כתום = הסתיים בלשונית מוסתרת; האייקון/השם, כי אין API לצבע), **continueAfterReload** – הערה: זה סותר את "אין שחזור אחרי רענון"; בעת היישום לממש כך שאחרי רענון נפתחת רק הצעה "להמשיך את השיחה האחרונה" שנקראת מה-transcripts, בלי מצב שנשמר בתוסף. **לשונית Web – לדלג** (תשתית ענן של Anthropic, אין שרת פנימי).
- Checkpoints: **מלא** – כפתור בכל הודעת משתמש עם fork / rewind code / שניהם + Esc Esc. **בדיקה נדרשת**: תמיכת ה-CLI 2.1.181 ב-rewind (בקשת בקרה). אם אין – רק fork (`--resume --fork-session`).
- רקע: **כפתור "העבר לרקע" + מפת משימות עם עצירה** (אירועי task_started/task_progress, בקשת stop_task; לבדוק מול ה-CLI). מזין גם את מפת הסוכנים משלב 2.
- אזהרה לתיעוד: בעת עדכון ה-spec יש לעדכן את סעיף "Out of scope" ואת סעיף ה-History לפי שלב זה.

#### בדיקות נוספות מול ה-CLI האמיתי
5. האם /rename כותב שם לקובץ ה-jsonl וניתן לקרוא אותו (שלב 4).
6. האם קיימת בקשת rewind ב-CLI 2.1.181 (שלב 4).
7. אילו אירועי task/background נשלחים בפועל (שלב 4).

### שלב 5 – שילוב סביבה (הוחלט)
- שרת IDE: **שרת WebSocket מקומי + הקשר (בחירה/קובץ) + getDiagnostics**. executeCode (Jupyter) – לא. **תנאי מקדים: בדיקת היתכנות לכל מה שקשור לשרת** לפני כל יישום (WebSocket בידיים בלי npm, פרוטוקול קובץ הנעילה ב-`~/.claude/ide/`, קבלה ע"י CLI 2.1.181). אם לא מתאפשר – חלופת הצ'יפים משלב 3.
- MCP: **דיאלוג ניהול מלא כולל הוספה והסרה מהממשק** (רשימה+סטטוס, הפעלה/כיבוי, חיבור מחדש, טופס הוספה). הוספה/הסרה כותבים לקובץ ההגדרות של ה-CLI – לבדוק שיטת כתיבה בטוחה (עדיף דרך פקודת `claude mcp` ולא עריכת JSON ידנית). OAuth – לא (offline).
- תוספים (Plugins) ו-Mods: **לדלג**.
- Git: **ללא שינוי** (עובד דרך Bash). סטטוס PR – לא. סטטוס Git בשורת התיבה – לא.
- שימוש: **שורת שימוש בסשן (טוקנים/עלות)** בלבד, מנתוני ה-CLI. דיאלוג /usage מלא – לא.

#### בדיקות נוספות מול ה-CLI האמיתי
8. היתכנות שרת IDE (WebSocket + lock file) – חוסם את שלבים 3 ו-5.
9. דרך כתיבה בטוחה להוספת/הסרת שרתי MCP (`claude mcp add/remove` מול עריכת settings).

### שלב 6 – תצוגה, נגישות, הגדרות, קיצורים (הוחלט)
- תצוגה: **Focus view** (מתג + הגדרה `focusView`), **חותמות זמן** (`showMessageTimestamps`), **spinnerVerbs**, **scrollToBottomOnSend**.
- טרמינל ונגישות: **הגדרת `useTerminal`** (הכפתור הראשי פותח טרמינל במקום צ'אט; משתמש בפקודת Open in Terminal משלב 1), **הגדרות נגישות וצבע** (`prefersReducedMotion`, תמיכה בערכות daltonized), **הכרזות לקורא מסך + תוויות דובר ("אתה"/"Claude") + ניווט לפי כותרות** (דורש בדיקה עם קורא מסך אמיתי).
- הגדרות נוספות: **`enableNewConversationShortcut` (Ctrl+N)**, **`environmentVariables`**. **לא**: `claudeProcessWrapper` (כרגע; אפשר להוסיף בעתיד), `usePythonEnvironment`, `enableReopenClosedSessionShortcut` (הקיצור Ctrl+Shift+T כבר הוחלט בשלב 4), `disableLoginPrompt`.
- קיצורים: **Ctrl+Esc** (מעבר עורך↔צ'אט); **Ctrl+Alt+C** כקיצור חלופי לפתיחה בלשונית חדשה (במקום Ctrl+Shift+Esc שנתפס ע"י Windows; Ctrl+Shift+Esc נשאר מוגדר).
  - **דרישה: כל הקיצורים ניתנים לשינוי ע"י המשתמש.** כל קיצור מוגדר כ-`contributes.keybindings` של פקודה עם שם, כך ש-VS Code Keyboard Shortcuts (Ctrl+K Ctrl+S) מאפשר לשנות כל אחד. להוסיף פקודה "Claude Code Local: Keyboard Shortcuts" שפותחת את מסך הקיצורים מסונן ל-`claude-local` (`workbench.action.openGlobalKeybindings`), וקיצורים בתוך ה-webview (Enter, Shift+Enter, Esc Esc) מוגדרים כהגדרות `claudeLocal.keybindings.*` או קריאה מ-keybindings.json של VS Code – להחליט בעת היישום (מגבלה: webview לא רואה את keybindings של VS Code אוטומטית).

### שלב 7 – פיצ'רי ענן/רשת (הוחלט)
- דפדפן (Chrome): **פיתוח עתידי** – המשתמש צפוי לבנות בעצמו שירות אוטומציית דפדפן (כנראה שרת MCP). בשלב זה אין תמיכה ב-Chrome. **להשאיר מקום בארכיטקטורה**: שרת כזה יתחבר דרך מנהל ה-MCP משלב 5, ואפשר יהיה להוסיף אז `@browser` / תפריט כלי דפדפן. לא ליישם כלום עכשיו.
- Remote Control: **לדלג**.
- הכתבה קולית: **לדלג**.
- /loop: **מחוון בצ'אט** ללא שמירה (מרווח, הרצה הבאה, כפתור עצירה). **בדיקה נדרשת**: אילו אירועים ה-CLI שולח כש-/loop פעיל. משימות ענן – לא.

#### בדיקה נוספת מול ה-CLI האמיתי
10. אילו אירועי loop נשלחים ב-stream-json (שלב 7).

### שלב 8 – פקודות משותפות, מצב אינטראקטיבי, Hooks (הוחלט)
- פקודות CLI שלא נתמכות ב-stream-json: **לזהות ולהסתיר/להסביר** – מסומנות בתפריט `/` כ"זמין בטרמינל בלבד" עם כפתור "פתח בטרמינל" (שלב 1). **בדיקה נדרשת**: אילו פקודות נתמכות בפועל.
- תור הודעות: **תור הודעות** (שליחה בזמן עבודה, Ctrl+Enter שולח מיד), **החלפת מודל/מצב באמצע עבודה**, **היסטוריית פרומפטים (חץ למעלה)** – בזיכרון בלבד. **בדיקה נדרשת**: האם ה-CLI מקבל הודעה באמצע תור ב-stream-json.
- מצב אינטראקטיבי: **פאנל /diff**, **רשימת משימות של Claude (TodoWrite)**, **מצב Shell עם `!`**. לא: הצעת פרומפט הבא, אימוג'י, /recap אוטומטי.
- Hooks והגדרות מנוהלות: **ללא קוד בתוסף** – הכל ב-CLI. (כפתור "פתח settings.json" כבר קיים בכרטיס השגיאה משלב 1.)

#### בדיקות נוספות מול ה-CLI האמיתי
11. אילו פקודות `/` נתמכות ב-stream-json (שלב 8).
12. הודעה באמצע תור, `!` shell ו-TodoWrite ב-stream-json (שלב 8).

פירוט מלא: `docs/litellm-gateway.md`. עיקרי הדברים והשינויים בהחלטות:
- **גישה מהתוסף לשער עובדת** (Extension Host של VS Code 1.91.1, `http` ו-`fetch`, בלי פרוקסי). ההחלטה "האם התוסף שולף את הרשימה" נשארת החלטת מדיניות בלבד.
- **רשימת המודלים:** `/v1/models` (בלי מפתח). **סינון:** לא אפשרי לפי יכולות מהשער (הנתונים לא אמינים). נחליט על סינון ידני (`modelDenylist`, ברירת מחדל `gemma3:27b`) והסתרה אוטומטית של מודלים עם `extra_body.output_config.format` (פלט JSON של כותרת: `qwen2.5-coder:7b`, `gemma4:31b`).
- **Effort:** נשאר מחוץ לתוכנית. `output_config.effort: high` קבוע בהגדרת השער.
- **חלון הקשר:** `num_ctx` המוגדר ל-`qwen3.8:27b` הוא **12288** (`max_input_tokens` 8192), אבל Claude Code שולח כ-24,700 טוקנים. **דחוף לבדוק אם נאכף** (בדיקת הפלאטו). אם נאכף, ההוראות נחתכות ומצב התכנון וההתנהגות הכללית נפגעים, ויש לבקש מהמנהל להגדיל את `num_ctx`.
- **מד הקשר:** `/utils/token_counter` ו-`/v1/messages/count_tokens` מספקים ספירה משוערת בלבד (`openai_tokenizer`). `get_context_usage` של ה-CLI נשאר המקור העיקרי, עם `CLAUDE_CODE_MAX_CONTEXT_TOKENS` לפי `num_ctx`.
