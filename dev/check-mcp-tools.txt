בדיקה מקדימה לחבילה H: האם ה-CLI מציג למודל כלים משרת MCP שלנו?
=================================================================

למה: חבילה H (ניווט בקוד) תעביר ל-Claude כלים דרך שרת MCP קטן של ההרחבה. אנחנו לא יודעים
עדיין שלושה דברים, והבדיקה הזו עונה עליהם לפני שבונים את השאר:
  א. האם ה-CLI שלך (2.1.246) מקבל שרת MCP מקומי דרך HTTP (type http), או שצריך stdio.
  ב. האם המודל המקומי באמת רואה את הכלים וקורא להם.
  ג. כמה טוקנים עולה רשימת הכלים (מושווה להרצה בלי שרת).

הבדיקה לא נוגעת בקבצים שלך. היא יוצרת תיקייה זמנית ב-%TEMP%, מפעילה שרת מקומי על 127.0.0.1
(עם אסימון אקראי) ומריצה את claude פעמיים-שלוש עם הודעה קצרה. הכלים בשרת לא עושים כלום
חוץ מלהחזיר מילה אקראית.

לפני שמריצים (דקה):
1. Node מותקן? ב-PowerShell:   node --version      (צריך 18 ומעלה)
2. הנתיב של claude-bin.exe (אותו אחד שמוגדר ב-claudeLocal.claudePath). לא claude.cmd.
3. המודל המקומי זמין. הטעינה הקרה לוקחת עד כ-285 שניות, וזה בסדר, ההרצה מחכה.
4. בדיקות עזר (אופציונלי, מעתיקים לי את התוצאה):
   & "<הנתיב>\claude-bin.exe" mcp add --help | Select-String "transport"
   & "<הנתיב>\claude-bin.exe" --help | Select-String "mcp-config|strict-mcp"

הרצה (מתוך התיקייה שבה נמצא הקובץ probe-mcp-standalone.js):

   cd <התיקייה>
   node probe-mcp-standalone.js --claude "<הנתיב>\claude-bin.exe" --out mcp-report.json

   אפשר להוסיף --model <שם המודל> אם רוצים מודל מסוים, ו--transport http (או stdio) לבדיקה אחת בלבד.
   משך: בערך 5 עד 20 דקות, בעיקר בגלל טעינת המודל.
   אם משהו נתקע: Ctrl+C. הדוח נשמר אחרי כל שלב, ומה שכבר רץ נשמר.

אחרי ההרצה:
5. להעתיק את הדוח ולהדביק לי בצ'אט:
   Get-Content mcp-report.json -Raw | Set-Clipboard
   (הדוח מכיל תשובות מודל ונתיבי תיקיות. כדאי לקרוא לפני שמדביקים.)
6. לנקות: למחוק את %TEMP%\claude-probe-mcp-* ואת התיקיות ~\.claude\projects\*claude-probe-mcp*

איך קוראים את התוצאה (אני אעשה את זה, אבל כדאי להכיר):
- serverSawToolsList = true:  ה-CLI התחבר ושלף את רשימת הכלים.
- serverSawPingCall = true ו-modelAnswerHasNonce = true:  המודל ראה את הכלי, קרא לו וקיבל תשובה.
- extraInputTokensVsBaseline:  כמה טוקנים נוספו בגלל ארבעת הכלים (שלושת הכלים המתוכננים ועוד ping).
- אם http נכשל ו-stdio עובד: נשתמש ב-stdio. אם שניהם נכשלים: נבדוק את stderr בדוח.
