כל הבדיקות הפתוחות בקובץ אחד - התוסף "Claude Code Local"
==========================================================

הקובץ הזה מחליף את ההרצה של כמה קבצי בדיקה נפרדים. כל הבדיקות כאן רצות על המחשב שלכם, מול ה-CLI האמיתי
(claude-bin.exe, גרסה 2.1.246) וב-VS Code 1.91.1 האמיתי. אף בדיקה לא משנה את הפרויקט שלכם: קבצי עזר נוצרים ב-TEMP.
המטרה: לדעת מה עובד ומה לא, ולהדביק לי את התוצאות בצ'אט כדי שאתקן ואחליט מה לבנות.

סדר מומלץ: הכנה, 1, 2, 3, 5, 6, 8, 9, 12, 13, ואז 4, 7, 10, 11 (אלה ב-VS Code). 14 אופציונלי.
בערך שעתיים בסך הכל. אפשר בחלקים. טעינה קרה של המודל יכולה לקחת עד כ-5 דקות בהודעה הראשונה, וזה לא תקלה.

------------------------------------------------------------
הכנה (פעם אחת)
------------------------------------------------------------
1. פתחו PowerShell (מקש Windows, הקלידו PowerShell, Enter). כל "הדביקו ב-PowerShell" אומר: להעתיק את הבלוק,
   קליק ימני בחלון (זה מדביק) ו-Enter.
2. הדביקו את שתי השורות הבאות. הן חייבות להיות מוגדרות באותו חלון PowerShell שבו מריצים את הבדיקות
   (אם סגרתם את החלון, הדביקו אותן שוב). אם תיקיית הפרויקט שלכם במקום אחר, שנו את $repo:

$claude = 'C:\Users\206861775\AppData\Local\Programs\ClaudeCode\claude-bin.exe'
$repo   = 'C:\Users\user\Claude-in-VSC'

3. ודאו ששניהם קיימים (צפוי: True ו-True):

Test-Path $claude; Test-Path $repo

   אם claude-bin.exe לא נמצא: where.exe claude  (או חפשו claude-bin.exe בתיקיית AppData\Local\Programs\ClaudeCode).
   חשוב: בכל הבדיקות משתמשים ב-claude-bin.exe ולא ב-claude או claude.cmd. העטיפה claude.cmd שואלת
   "Select model number" לפני כל הרצה ותתקע את הבדיקה.

4. גרסת ה-CLI (העתיקו לי): & $claude --version
5. גרסת Node (צריך 18 ומעלה): node --version
6. הרצת התוסף ב-VS Code לבדיקות הידניות: ב-PowerShell, אחרי cd לתיקיית פרויקט כלשהו שעליו תרצו לעבוד:

code --extensionDevelopmentPath=$repo

   נפתח חלון VS Code חדש ("Extension Development Host") עם התוסף פעיל. בדיקות ה-VS Code עושים בחלון הזה.
   אם הפקודה code לא מוכרת: ב-VS Code לחצו Ctrl+Shift+P והקלידו "Shell Command: Install 'code' command in PATH".
7. אימות הגדרת הנתיב בתוסף: Ctrl+, וחפשו claudeLocal.claudePath. הערך חייב להיות הנתיב המלא ל-claude-bin.exe
   (כמו $claude למעלה), לא "claude".
8. יומן התוסף: Ctrl+Shift+P ואז "Claude Code Local: הצגת יומן". שורות מהיומן מעתיקים בסימון בעכבר ו-Ctrl+C.
   (יש גם "העתקת יומן" שמעתיקה הכול.)

בדיקה 2 - האם ה-CLI מעלה קובץ שמוזכר עם @ (כמה דקות)
------------------------------------------------------------
למה: התוסף שולח "@נתיב" בהודעה. אם ה-CLI מרחיב את זה במצב stream-json, אין צורך שהתוסף יעשה זאת בעצמו
(חבילה I שלב 2). אם לא, צריך את ההוראה המפורשת "קרא את הקובץ".
הבדיקה חוסמת את כלי הקריאה, ולכן אם המודל עונה את המילה הסודית, ה-CLI הוא שהעלה את התוכן.
הדביקו ב-PowerShell (משתמש ב-$claude מההכנה):

$dir = Join-Path $env:TEMP 'cl-at-test'
New-Item -ItemType Directory -Force $dir | Out-Null
Set-Content -Path (Join-Path $dir 'secret.txt') -Value 'The secret word of this file is PINEAPPLE-7731' -Encoding utf8
$abs = (Join-Path $dir 'secret.txt') -replace '\\','/'
function Ask($label, $text) {
  Write-Host "=== $label" -ForegroundColor Cyan
  $msg = @{ type = 'user'; message = @{ role = 'user'; content = @(@{ type = 'text'; text = $text }) } } | ConvertTo-Json -Depth 6 -Compress
  $out = $msg | & $claude -p --input-format stream-json --output-format stream-json --verbose --disallowedTools 'Read,Glob,Grep,Bash,Edit,Write,WebFetch'
  foreach ($line in $out) { try { $j = $line | ConvertFrom-Json } catch { continue }; if ($j.type -eq 'result') { Write-Host ("תשובה: " + $j.result) } }
}
Push-Location $dir
Ask '1: @ עם נתיב מלא' "@$abs מהי המילה הסודית בקובץ? ענו במילה אחת."
Ask '2: @ עם נתיב יחסי' "@secret.txt מהי המילה הסודית בקובץ? ענו במילה אחת."
Ask '3: בקרה, בלי @ (אמור להיכשל)' "מהי המילה הסודית בקובץ secret.txt שבתיקייה הנוכחית? ענו במילה אחת."
Ask '4: הוראה מפורשת, בלי כלים' "התחל את העבודה מהקובץ @$abs. מהי המילה הסודית בו? ענו במילה אחת."
Pop-Location

איך לקרוא:
- בדיקה 3 (בקרה) חייבת להיכשל. אם היא מצליחה, הכלים לא נחסמו והבדיקה לא תקפה.
- בדיקה 1 עונה PINEAPPLE-7731: ה-CLI מרחיב נתיב מלא. התוסף יכול להסתפק ב-@.
- בדיקה 1 וגם 4 נכשלות: ה-CLI לא מרחיב (צפוי, כי הכלים חסומים); בתוסף האמיתי המודל יפתח את הקובץ בעצמו.
- בדיקה 2 מראה אם נתיב יחסי עובד.
מה להעתיק: ארבע שורות "תשובה:".
ניקוי: Remove-Item -Recurse $env:TEMP\cl-at-test

בדיקה 3 - /btw כתהליך נפרד מול ה-CLI האמיתי (כמה דקות)
------------------------------------------------------------
למה: התוסף מריץ כל שאלת /btw כתהליך קצר וחד-פעמי: claude -p --output-format json --tools "" --no-session-persistence
(השאלה ב-stdin). בדיקות היחידה מוכיחות רק שהתוסף שולח את הדגלים, לא מה ה-CLI עושה איתם.

שלב א. דגלים. ב-PowerShell:

& $claude --help | Select-String -Pattern 'no-session-persistence|--tools'

צפוי: שני הדגלים מופיעים. אם אחד חסר, עצרו ודווחו.

שלב ב. הדביקו את כל הבלוק:

$dir = Join-Path $env:TEMP 'cl-btw-proc'
New-Item -ItemType Directory -Force $dir | Out-Null
Push-Location $dir
'--- א. תשובה רגילה ---'
'What is 2+2? Answer with the number only.' | & $claude -p --output-format json --tools "" --no-session-persistence
'--- ב. בקשת כלי (צפוי: לא מריץ, מסביר שאין כלים) ---'
'Use a tool to list the files in the current folder.' | & $claude -p --output-format json --tools "" --no-session-persistence
'--- ג. היסטוריה (צפוי: לא יודע על שיחה קודמת) ---'
'What did I ask you before this message? If nothing, say NONE.' | & $claude -p --output-format json --tools "" --no-session-persistence
Pop-Location
'--- ד. אין קובץ שיחה חדש ---'
Get-ChildItem (Join-Path $env:USERPROFILE '.claude\projects') -Recurse -Filter *.jsonl | Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-3) } | Select-Object FullName

צפוי: א. JSON עם "result":"4" ו-"is_error":false. ב. אין רשימת קבצים בפועל ואין tool_use. ג. NONE או "אין הקשר".
ד. אין קובץ jsonl חדש של התיקייה cl-btw-proc.

שלב ג. ב-VS Code (Extension Development Host), בשיחה פתוחה:
  1. שלחו "זכור את המספר 4242. ענה רק: אישור". המתינו לתשובה.
  2. כתבו "/btw איזה מספר ביקשתי שתזכור?" ושלחו. צפוי: נפתחת חלונית "שאלה צדדית" ליד הצ'אט, ותשובה שאינה 4242.
  3. כתבו "/btw" לבד. צפוי: החלונית נפתחת (או מקבלת מיקוד) בלי שאלה.
  4. בחלונית כתבו "מה ההבדל בין let ל-const?" ואחר כך "ומה לגבי var?". צפוי: התשובה השנייה מתייחסת לראשונה.
  5. שלחו /btw בזמן ש-Claude עונה על הודעה רגילה. צפוי: החלונית עונה והתשובה הראשית לא מופרעת.
  6. בזמן שהחלונית חושבת לחצו על העצירה. צפוי: "השאלה בוטלה." בלי שגיאה. "ניקוי שיחה" מנקה הכול.
  7. סגרו ופתחו שוב עם /btw. צפוי: ריקה. ההיסטוריה של השיחה הראשית לא מכילה את שאלות ה-/btw.
מה להעתיק: פלט שלב ב, ועבר/נכשל לכל סעיף בשלב ג (בכשלון גם שורות [btw] מהיומן).
ניקוי: Remove-Item -Recurse $env:TEMP\cl-btw-proc

בדיקה 4 - שיוך קבצים לשיחה ב-VS Code (כ-20 דקות)
------------------------------------------------------------
הכנה: בחלון ה-VS Code של התוסף, על פרויקט כלשהו, צרו שני קבצי טקסט: a.txt עם "המילה היא ענבר" ו-b.txt עם
"המילה היא תפוז". פתחו שיחה חדשה לכל בדיקה.

4.1 רשימת @
  1. בתיבה הקלידו @ . צפוי: רשימת קבצים ותיקיות (בלי קבצים ש-.gitignore מתעלם מהם).
  2. בחרו a.txt עם Enter. צפוי: בתיבה @ ואחריו נתיב מלא (C:/...).
  3. בחרו תיקייה. צפוי: הרשימה מציגה את התוכן הישיר שלה.
  4. בחירה מהרשימה לא מפעילה פקודת / ולא שולחת כלום.
4.2 קיצורים וגרירה
  1. פתחו קובץ בעורך ולחצו Alt+K. צפוי: @ עם הנתיב נכנס לתיבה.
  2. גררו קובץ מהסייר לתיבה כשמקש Shift לחוץ. צפוי: @ עם נתיב מלא.
  3. גררו קובץ תמונה מחוץ ל-VS Code. צפוי: תמונה מצורפת. אם לא: רשמו ושורת [drop] מהיומן.
4.3 מה ה-CLI עושה עם @ (תלוי בבדיקה 2)
  1. שיחה חדשה: @a.txt מהרשימה ואחריו "מהי המילה בקובץ? ענו במילה אחת." צפוי: ענבר.
     האם הופיעה שורת כלי "קריאה" לפני התשובה? בלי שורה: ה-CLI העלה את הקובץ. עם שורה: המודל פתח אותו בעצמו.
  2. שיחה חדשה, @ של תיקייה ואחריו "אילו קבצים יש בתיקייה?" צפוי: רשימה בלבד, בלי תוכן הקבצים.
4.4 כפתור "מקור השיחה"
  1. שיחה חדשה. צפוי: בשורת הכלים "מקור השיחה: ללא".
  2. לחצו. צפוי: נפתח סייר הקבצים של המערכת בתיקיית הפרויקט. בחרו a.txt. הכפתור מציג 📄 a.txt.
  3. שלחו "מה המילה בקובץ שהתחלנו ממנו? ענו במילה אחת." צפוי: ענבר.
  4. שלחו עוד הודעה על הקובץ. ההוראה לא אמורה לחזור.
  5. לחצו שוב. צפוי: תפריט "בחירת קובץ או תיקייה אחרים…" / "הסרת המקור". בחרו אחרים: b.txt. שלחו
     "באיזה קובץ מתחילה העבודה?" צפוי: תפוז.
  6. לחצו שוב ובחרו תיקייה. צפוי: הכפתור מציג 📁 ושם התיקייה.
  7. "הסרת המקור". צפוי: חוזר ל"מקור השיחה: ללא".
4.5 בלי שמירה (כמו שהוחלט)
  1. בחרו a.txt, שלחו הודעה, סגרו את השיחה ופתחו מחדש מהרשימה ☰. צפוי: "מקור השיחה: ללא". זה תקין.
  2. Developer: Reload Window. צפוי: אותו דבר.
4.6 תמונה בלבד
  1. הדביקו תמונה (Ctrl+V) בלי טקסט. צפוי: השליחה פעילה ועובדת.
  2. אם המודל לא תומך בתמונות: צפוי הסבר בעברית לפני שגיאת השרת.
מה להעתיק: עבר/נכשל לכל סעיף. ב-4.3 איזו אפשרות התקבלה.

בדיקה 5 - החלפת מודל וחלון ההקשר (F-8 ו-F-9, כ-10 דקות)
------------------------------------------------------------
למה: התיקון נבדק מול גרסה 2.1.317. אצלכם רצה 2.1.246, ולכן צריך לוודא שגם שם זה עובד.

שלב 1 - מודל ברירת המחדל (F-9). ב-VS Code, עם היומן פתוח:
  1. שיחה חדשה על "ברירת מחדל", הודעה קצרה ("היי").
  2. בלוג חפשו שורה שמתחילה ב-[context]. צפוי: used=... max=64000 model=qwen3.8:27b
     - טוב: model בלי [1m] ובלי המילה capped.
     - חלקי: "(CLI max=1000000, capped)" ו-model=qwen3.8:27b[1m]. המד נכון, אבל הדחיסה האוטומטית לא תופעל בזמן. דווחו.
     - תקלה: ההודעה הראשונה נכשלת ("Invalid model name"/"model not found"). פתחו
       C:\Users\206861775\.claude\settings.json, ואם יש "model" עם [1m] (למשל "opus[1m]") מחקו את [1m]. דווחו בכל מקרה.
  3. אחרי שורת [spawn] start אמורה להופיע:
     [spawn] --settings env {"CLAUDE_CODE_MAX_CONTEXT_TOKENS":"64000","CLAUDE_CODE_DISABLE_1M_CONTEXT":"1"}

שלב 2 - החלפת מודל (F-8):
  1. באותה שיחה החליפו מודל ל-qwen2.5:7b ושלחו הודעה קצרה (הטעינה הראשונה יכולה לקחת כמה דקות).
  2. בלוג, אחרי ההחלפה, חפשו שורות stderr עם [claude-code:unrecognized_model].
     - טוב: כולן מציינות "model":"qwen2.5:7b" (או שאין שורה כזו).
     - תקלה: "model":"qwen3.8:27b" עם "query_source":"generate_session_title" אחרי ההחלפה.
  3. מיד אחר כך (תוך 5 דקות), ב-PowerShell:

Invoke-RestMethod http://172.27.5.5:11435/api/ps | Select-Object -ExpandProperty models | Select-Object name, context_length | Format-Table -AutoSize

     השרת משותף, ולכן ייתכנו מודלים של משתמשים אחרים. חשוב ש-qwen3.8:27b לא נטען מחדש בגלל ההודעה שאחרי ההחלפה.
מה להעתיק: שורות [spawn] ו-[context], שורות stderr, ותוצאת /api/ps.

בדיקה 6 - חלון ההקשר של qwen3.8:27b (דקה)
------------------------------------------------------------
למה: 64,000 נמדד רק עבור gemma4:26b. עבור qwen3.8:27b נמדד "לפחות 50,000" ו-64,000 הוא הנחה.

2. תוך 5 דקות, ב-PowerShell:

Invoke-RestMethod http://172.27.5.5:11435/api/ps | Select-Object -ExpandProperty models | Select-Object name, context_length | Format-Table -AutoSize

3. בשורת qwen3.8:27b העמודה context_length היא החלון האמיתי. 64000: אין מה לשנות. מספר אחר: ב-claudeLocal.environmentVariables
   שנו את CLAUDE_CODE_MAX_CONTEXT_TOKENS אליו (וכך נדע שצריך את claudeLocal.modelContextWindows). המודל לא ברשימה: חזרו על שלב 1 מהר יותר.
הבדיקה רק קוראת. מה להעתיק: התוצאה.

------------------------------------------------------------
בדיקה 7 - התוסף ב-VS Code (כ-25 דקות)
------------------------------------------------------------
פותחים שיחה חדשה לפני כל קבוצה.
7.1 קיצורי מקלדת
  1. Ctrl+Alt+C. צפוי: הצ'אט נפתח או מקבל מיקוד.
  2. Ctrl+Alt+E בעורך טקסט. צפוי: המיקוד עובר לצ'אט; שוב: חוזר לעורך. תפריט התחל של Windows לא נפתח.
  3. סגרו שיחה שיש בה הודעות ולחצו Ctrl+Shift+T. צפוי: נפתחת מחדש. אם לא: רשמו אם הצ'אט היה בסרגל הצד או בלשונית.
7.2 פקודות התוסף ב-/
  1. הקלידו /. צפוי: בראש הרשימה קבוצה "פקודות של התוסף" עם plan, plan open, diff.
  2. בחרו plan. צפוי: "עברתם למצב תכנון"; בחירה חוזרת: "כבר במצב תכנון".
  3. /plan open בלי תוכנית. צפוי: הודעה שעדיין אין תוכנית.
7.3 תיבת ההודעה
  1. חץ מעוגל בכותרת (חזרה לנקודת שמירה). צפוי: נפתחת רשימת נקודות שמירה.
  2. הודעה ארוכה (יותר מ-8 שורות). צפוי: מכווצת עם "הצג עוד"/"כווץ".
  3. כבו את שרת המודלים ושלחו. צפוי: תיבת שגיאה עם "נסה שוב". הדליקו ולחצו: אותה הודעה נשלחת שוב.
7.4 נוסחאות LaTeX
