רשימת הבדיקות החובה - תוסף "Claude Code Local"
==============================================

קובץ אחד, צעד אחר צעד. עושים לפי הסדר, צעד אחד בכל פעם. אחרי כל סעיף יש "עבר", "נכשל" ו"מה לשלוח לי".
אין צורך באינטרנט באף שלב. את כל מה שמסומן "שלחו לי" מדביקים בצ'אט אחרי הסעיף (או בסוף הכול).
בסוף הקובץ (סעיף 8) טבלת סיכום למילוי.

סימונים: [עבר] = התוצאה המצופה קרתה. [נכשל] = לא קרתה, או קרה משהו אחר. אם לא בטוחים - זה נכשל, ותארו מה ראיתם.

כמה זמן: בערך שעה וחצי בסך הכול. אפשר בחלקים. סדר מומלץ: 1, 2, 3, 4, 7, 5, 6.

סעיף 1 - הכנה (חובה לפני כל השאר)
------------------------------------------------------------
מטרה: התוסף החדש מותקן ופעיל, ואתם יודעים איפה היומן.

תנאים מוקדמים: קובץ ה-VSIX האחרון במחשב (בלי אינטרנט), פרויקט קטן לבדיקה שיש בו לפחות שני קבצים: a.js ו-b.js
(כל תוכן, למשל כמה שורות קוד).

צעדים:
1.1 סגרו את כל חלונות VS Code.
1.2 פתחו PowerShell (מקש Windows, הקלידו PowerShell, Enter).
1.3 הקלידו, עם הנתיב האמיתי של קובץ ה-VSIX שלכם, ולחצו Enter:
    code --install-extension C:\path\to\claude-in-vsc.vsix --force
    צפוי: ההודעה "was successfully installed".
    (אם הפקודה code לא מוכרת: ב-VS Code, Ctrl+Shift+P, הקלידו "Shell Command: Install 'code' command in PATH", Enter, ופתחו PowerShell חדש.)
1.4 פתחו את VS Code על תיקיית הבדיקה: בחלון PowerShell הקלידו  code "C:\path\to\test-project"  ו-Enter.
1.5 ב-VS Code לחצו Ctrl+Shift+P, הקלידו Developer: Reload Window ולחצו Enter. (זה מבטיח שהגרסה החדשה נטענת.)
1.6 לחצו Ctrl+Shift+X (תוספים), חפשו "Claude Code Local" ובדקו שמספר הגרסה הוא הגרסה שהתקנתם.
1.7 פתחו את ערוץ היומן: Ctrl+Shift+P, הקלידו Claude Code Local: הצגת יומן (claude-local.showLogs), Enter.
    צפוי: נפתח לוח Output עם הערוץ "Claude Code Local".
1.8 בלוח Output, בתפריט הנפתח שבפינה, ודאו שנבחר "Claude Code Local".
1.9 איך מעתיקים את היומן: Ctrl+Shift+P, הקלידו Claude Code Local: העתקת יומן (claude-local.copyLogs), Enter.
    זה מעתיק את כל היומן ללוח. הדביקו למחברת (Notepad) כדי לחפש שורות עם Ctrl+F.
1.10 פתחו את הצ'אט: Ctrl+Alt+C.
1.11 כדי שהיומן יהיה מפורט יותר, בהגדרות (Ctrl+,) חפשו claudeLocal.logLevel ובחרו debug. (נחזיר ל-info בסוף.)

עבר: התוסף מותקן, הצ'אט נפתח, ערוץ היומן מציג שורות.
נכשל: שגיאת התקנה, הצ'אט לא נפתח, או שערוץ היומן ריק לגמרי.
שלחו לי: אם נכשל - את הודעת השגיאה המלאה. אם עבר - מספר הגרסה של התוסף ושל ה-CLI (ב-PowerShell: claude --version).

סעיף 3 - אישור תוכנית (ExitPlanMode)
------------------------------------------------------------
מטרה: להכריע אם ה-CLI שולח קריאת ExitPlanMode כשהמודל מסיים תוכנית במצב תכנון (מחליט אם בונים כפתורי אישור תוכנית).

תנאים מוקדמים: סעיף 1 הושלם. שיחה חדשה, בלי הודעות.

צעדים:
3.1 פתחו שיחה חדשה בצ'אט.
3.2 בתיבת ההודעה הקלידו /  ובחרו מקבוצת "פקודות של התוסף" את "plan". (או לחצו על כפתור המצב ובחרו "תכנון".)
    צפוי: הודעה "עברתם למצב תכנון" והכפתור מציג "תכנון".
3.3 שלחו: Make a plan to add a function sum(a,b) to a.js, and tell me when the plan is ready.
3.4 חכו עד שהמודל מסיים לענות (הכפתור "עצירה" חוזר ל"שליחה").
3.5 הסתכלו בצ'אט: האם מופיע כרטיס או שורת כלי בשם ExitPlanMode (או "יציאה ממצב תכנון")? רשמו כן/לא.
3.6 הקלידו /plan open ולחצו Enter.
    המשמעות: התוסף שומר טקסט תוכנית רק אם הגיעה קריאת ExitPlanMode. אם נפתח מסמך עם התוכנית - הקריאה הגיעה.
3.7 חפשו ביומן (Ctrl+Shift+P, "העתקת יומן", הדביקו במחברת) את המילה ExitPlanMode. (עם logLevel=debug ייתכן שורה; אם אין שורה, ההכרעה היא לפי 3.5 ו-3.6.)
3.8 אם המודל שאל אתכם שאלה (כרטיס שאלה עם אפשרויות) במקום להציג תוכנית - רשמו זאת: זה AskUserQuestion ולא ExitPlanMode.

עבר (ExitPlanMode מגיע): נפתח מסמך תוכנית ב-3.6, ו/או ראיתם כרטיס/שורה ExitPlanMode ב-3.5.
נכשל (לא מגיע): 3.6 מציג "עדיין אין תוכנית", ואין ExitPlanMode בצ'אט וביומן.
לא חד-משמעי: המודל ענה בטקסט בלבד בלי תוכנית - חזרו על 3.3 עם נוסח: "Write a step by step plan, then finish planning." ועל 3.4-3.6 (פעם אחת).

שלחו לי: "מגיע" או "לא מגיע", ההודעה שהוצגה ב-/plan open, ואם יש - שורת היומן עם ExitPlanMode. אם ראיתם AskUserQuestion - ציינו.

סעיף 4 - בדיקות 7 ו-8 מ-check-all (מועתקות במלואן)
------------------------------------------------------------
מטרה: לוודא ב-VS Code אמיתי את מה שנבנה בחבילות הקודמות (קיצורים, פקודות /, תיבת הודעה, LaTeX, צ'יפים).
פותחים שיחה חדשה לפני כל קבוצה.

--- בדיקה 7 ---

7.1 קיצורי מקלדת
  1. Ctrl+Alt+C. צפוי: הצ'אט נפתח או מקבל מיקוד.
  2. Ctrl+Alt+E בעורך טקסט. צפוי: המיקוד עובר לצ'אט; שוב - חוזר לעורך. תפריט התחל של Windows לא נפתח.
  3. סגרו שיחה שיש בה הודעות (X בלשונית או מהרשימה) ולחצו Ctrl+Shift+T. צפוי: השיחה נפתחת מחדש.
     אם לא נפתחת: רשמו אם הצ'אט היה בסרגל הצד או בלשונית, ואם היה קובץ פתוח בעורך באותו רגע.

7.2 פקודות התוסף ב-/ (F-5, F-13)
  1. בתיבה הקלידו / . צפוי: בראש הרשימה קבוצה "פקודות של התוסף" עם plan, plan open, diff.
  2. בחרו plan. צפוי: הודעה "עברתם למצב תכנון" וכפתור המצב מציג תכנון. בחירה חוזרת: "כבר במצב תכנון".
  3. הקלידו /plan open בלי תוכנית. צפוי: הודעה שעדיין אין תוכנית.

7.3 תיבת ההודעה
  1. הדביקו תמונה בלי טקסט ולחצו שליחה (F-11). צפוי: נשלחת.
  2. גררו קובץ תמונה מחוץ ל-VS Code לתיבה. צפוי: מצורפת. אם לא, העתיקו את שורת [drop] מהיומן.
  3. לחצו על הכפתור בכותרת של חזרה לנקודת שמירה (חץ מעוגל, F-12). צפוי: נפתחת רשימת נקודות השמירה.
  4. הקלידו הודעה ארוכה (יותר מ-8 שורות) ושלחו. צפוי: ההודעה מוצגת מכווצת עם "הצג עוד"; לחיצה מרחיבה, "כווץ" מכווץ.
  5. גרמו לשגיאה (למשל כבו את שרת המודלים, או סגרו את הרשת) ושלחו הודעה. צפוי: תיבת השגיאה כוללת כפתור "נסה שוב".
     הדליקו את השרת ולחצו "נסה שוב". צפוי: אותה הודעה נשלחת שוב.

7.4 נוסחאות (LaTeX)
  1. שלחו: כתוב את נוסחת השורשים של משוואה ריבועית בפורמט LaTeX עם $$ ... $$ ואת x^2 בתוך שורה עם $...$.
  2. צפוי: נוסחה מעוצבת (לא טקסט גולמי עם $). הסימן $ בטקסט רגיל, כמו "5$ ו-10$", נשאר כמו שהוא.

7.5 הגדרות
  1. הגדרות VS Code, חפשו collapseUserMessageLines. צפוי: ברירת מחדל 8; 0 מבטל כיווץ.

7.6 הקשר מהעורך וה-diff
  1. סמנו כמה שורות בקובץ ולחצו Alt+K. צפוי: בתיבה מוסף @path#שורות, ובצ'אט מופיעים צ'יפים עם הקובץ והשורות. הסרת צ'יפ מונעת את שליחתו.
  2. בקשו מ-Claude לערוך קובץ קטן (למשל: הוסף שורת הערה בראש הקובץ). צפוי: מוצג diff עם בלוקים לאישור
     (CodeLens, או רשימת בחירה אם diffEditor.codeLens כבוי). אישור בלוק מחיל אותו, דחייה לא.
  3. הקלידו /diff אחרי העריכה. צפוי: רשימת הקבצים ש-Claude שינה; בחירה בקובץ פותחת השוואה בעורך.

מה לשלוח לבדיקה 7: לכל סעיף "עבר" או "נכשל" ומה קרה בפועל. אם משהו נראה מוזר בעיצוב - צילום מסך.

--- בדיקה 8 --- תגית הקובץ ותגית השורות (חבילה K)
הכנה: פרויקט פתוח עם שני קבצים לפחות (a.js, b.js), ויומן התוסף פתוח (Output > Claude Code Local).

8.1 מצב ריק ואוטומטי
  1. סגרו את כל העורכים ופתחו את הצ'אט. צפוי: מעל התיבה שתי תגיות אפורות מקווקוות: "אין קובץ" ו"אין בחירה".
  2. פתחו את a.js. צפוי: תגית הקובץ מציגה a.js עם אייקון קובץ; "אין בחירה" נשאר.
  3. סמנו שורות 3-5 ב-a.js. צפוי: תגית השורות "שורות 3-5".
  4. שלחו "מה יש בשורות שסימנתי?". צפוי: ביומן "editor context attached"; המודל עונה על השורות.
  5. שלחו הודעה נוספת בלי לשנות דבר. צפוי: ההקשר לא נשלח שוב (אין "editor context attached" חדש ביומן).

8.2 בחירה ידנית והחזרה לאוטומטי
  1. לחצו על תגית הקובץ. צפוי: תפריט "אוטומטי" (מסומן), "בחר קובץ...", ורשימת האחרונים.
  2. "בחר קובץ..." ובחרו את b.js. צפוי: חלון הבחירה של VS Code נפתח בתיקיית הפרויקט; התגית מציגה b.js עם מסגרת מודגשת;
     תגית השורות ריקה (הבחירה ב-a.js, לא ב-b.js).
  3. שלחו "מה הקובץ שתייגתי?". צפוי: המודל עונה b.js. אחרי השליחה התגית חוזרת ל-a.js, במסגרת כתומה, עם הכיתוב "הוחזר למצב אוטומטי" בכתום לצד התגית.
  4. הקלידו תו אחד בתיבה. צפוי: הסימון הכתום נעלם.
  5. לחצו על התגית. צפוי: b.js מופיע ברשימת האחרונים. בחרו בו. צפוי: התגית מציגה b.js.
  6. לחצו על ה-X בתגית. צפוי: חוזרת לאוטומטי (a.js), בלי סימון כתום.

8.3 תיקייה, מחוץ לפרויקט, כפילות
  1. "בחר קובץ..." ובחרו תיקייה. צפוי: אייקון תיקייה ושם התיקייה. שלחו "מה יש בתיקייה?"; המודל מפרט את תוכנה.
  2. "בחר קובץ..." ובחרו קובץ מחוץ לפרויקט (למשל במסמכים). צפוי: ריחוף על התגית מראה "מחוץ לפרויקט";
     בשליחה Claude מבקש הרשאה לקרוא אותו (כרטיס הרשאה רגיל).
  3. במצב אוטומטי עם a.js, הקלידו @ ובחרו את a.js מהרשימה, ושלחו. צפוי: ברשימת @ הקבצים האחרונים מופיעים ראשונים;
     ביומן אין "editor context attached" (אותו קובץ נשלח פעם אחת, דרך הטקסט).
  4. Alt+K בעורך של b.js. צפוי: @נתיב נכנס לתיבה, ו-b.js מופיע ברשימת האחרונים של התגית.

8.4 שמירה והגדרות
  1. ערכו את a.js בלי לשמור (נקודה לבנה בלשונית), ושלחו "מה השורה האחרונה ב-a.js?". צפוי: הקובץ נשמר לפני השליחה, והתשובה כוללת את השינוי.
  2. הגדרות, colorMode = daltonized, וחזרו על 8.2 צעד 3. צפוי: הסימון הכתום ("הוחזר למצב אוטומטי") נראה בבירור.

מה לשלוח לבדיקה 8: לכל סעיף "עבר" או "נכשל" ומה קרה בפועל; צילום מסך של התגיות אם משהו נראה מוזר.

עבר (סעיף 4 כולו): כל הצעדים נתנו את "צפוי". נכשל: כל צעד שלא. רשמו את מספר הצעד המדויק (למשל 8.2.3).

סעיף 5 - כלי הניווט בקוד (dev\run-h-checks.ps1)
------------------------------------------------------------
מטרה: לוודא שה-CLI רואה את כלי ה-MCP המקומיים (ניווט בקוד), שהמודל קורא להם ומקבל תשובה, ולמדוד את עלות הטוקנים.

תנאים מוקדמים: checkout מלא (תיקיית dev), Node.js 18 ומעלה (node --version), שרת המודלים זמין. הבדיקה לוקחת 5 עד 20 דקות
(רובן טעינת המודל הקר). לא נדרש VS Code.

צעדים:
5.1 פתחו PowerShell ועברו לתיקיית dev של התוסף:
    cd "C:\path\to\Claude in VSC\dev"
5.2 מצאו את הנתיב של claude-bin.exe (לא claude.cmd). הקלידו:
    Get-ChildItem "$env:LOCALAPPDATA\Programs\ClaudeCode" -Recurse -Filter claude-bin.exe | Select-Object -ExpandProperty FullName
5.3 שמרו את הנתיב במשתנה (החליפו בנתיב מ-5.2):
    $claude = "C:\Users\...\claude-bin.exe"
5.4 הריצו:
    powershell -ExecutionPolicy Bypass -File .\run-h-checks.ps1 -ClaudePath $claude -Model "qwen3.8:27b" -CopyReport
    (אם PowerShell כבר מריץ סקריפטים, אפשר גם:  .\run-h-checks.ps1 -ClaudePath $claude -Model "qwen3.8:27b" -CopyReport )
5.5 חכו עד שהסקריפט מסתיים (הוא מדפיס "Report:" ו"Report copied to the clipboard").
5.6 צפוי בפלט, בסעיף "== Summary ==", לכל transport (http ו-stdio) שורה אחת:
    [PASS] transport=http
    [PASS] transport=stdio
    ובשורות מתחתן, כולן True:  (a) server got initialize / (a) server got tools/list / (b) model called ping / (b) model answer has nonce
    ושורה "(c) extra input tokens:" עם מספר.
5.7 הדביקו את הדוח שהועתק ללוח (Ctrl+V) בצ'אט.

עבר: [PASS] לשני ה-transport, וארבע שורות ה-True.
נכשל: [FAIL] באחד מהם. שימו לב לשורת "stderr (last part)" שהסקריפט מדפיס.
שלחו לי: את כל חלק "== Summary ==" ואת הדוח מהלוח (mcp-report.txt). קראו אותו קודם: הוא כולל נתיבי תיקיות ותשובות מודל.

אופציונלי, לניקוי אחרי: .\run-h-checks.ps1 -ClaudePath $claude -Cleanup

סעיף 6 - מד ההקשר/שימוש והחלפת מודל
------------------------------------------------------------
מטרה: לוודא שמד השימוש מציג נכון, שחלון ההקשר הוא 64,000, ושהחלפת מודל לא טוענת מודל נוסף בשרת.

תנאים מוקדמים: סעיף 1. גישה לשרת Ollama הפנימי (172.27.5.5:11435). בבדיקה 6.3 מתבצעת טעינה של qwen2.5:7b בשרת משותף.

6.1 מד השימוש
  1. בשיחה חדשה שלחו הודעה קצרה (למשל: היי).

7ד. תפריטי @ ו-/ באמצע משפט
  מטרה: התפריטים נפתחים גם באמצע משפט (אחרי רווח), הבחירה מוסיפה במקום הנכון בלי למחוק את הטקסט שאחריה, ו-/ בתוך נתיב (a/b) לא פותח תפריט.
  תנאים: שיחה חדשה, תיבת הודעה ריקה.
  1. הקלידו: please look at  (אחרי "at" רווח), והקלידו @. צפוי: נפתח תפריט הקבצים.
  2. בחרו קובץ (a.js). צפוי: נכנס @a.js (או נתיב) במקום של ה-@, והטקסט "please look at" נשאר.
  3. נקו את התיבה. הקלידו: fix  tests please  (שני רווחים אחרי fix, כלומר מקום ריק באמצע).
  4. העבירו את הסמן בין שני הרווחים (חצים או לחיצה) והקלידו @. צפוי: נפתח תפריט הקבצים באמצע המשפט.
  5. בחרו קובץ. צפוי: הקובץ נכנס בדיוק בנקודה, והמילה "tests please" אחריו נשארת שלמה (לא נמחקה ולא הוחלפה).
  6. נקו את התיבה. הקלידו: run  ואז רווח והקלידו /. צפוי: נפתח תפריט הפקודות באמצע המשפט (אחרי רווח).
  7. בחרו פקודה (למשל diff). צפוי: היא נכנסת במקום, והמילה "run" נשארת.
  8. נקו את התיבה. הקלידו בלי רווחים: a/b
  9. צפוי: אחרי ה-/ לא נפתח תפריט פקודות.
  10. הקלידו עוד: path src/x  ואז בדקו. צפוי: גם כאן, ה-/ בתוך src/x לא פותח תפריט.
  11. נקו. הקלידו / בתיבה ריקה. צפוי: התפריט נפתח כרגיל (לא נשבר).
  12. נקו. הקלידו: open /re  (רווח לפני ה-/). צפוי: נפתח תפריט הפקודות (זו התנהגות מוכרת: גם נתיב כמו /re אחרי רווח פותח אותו).
      לחצו Escape. צפוי: התפריט נסגר. לחצו Enter. צפוי: ההודעה "open /re" נשלחת כמו שהיא, בלי שנבחרה פקודה.
      עבר: Escape סוגר ו-Enter שולח את הטקסט. נכשל: אחרי Escape הטקסט הוחלף בפקודה, או שהתפריט לא נסגר.
  עבר: כל "צפוי" התקיים.
  נכשל: התפריט לא נפתח באמצע משפט, הבחירה מחקה טקסט אחריה, או ש-/ בתוך נתיב פתח תפריט.
  שלחו לי: מספרי הצעדים שנכשלו ומה נראה בתיבה (הטקסט המדויק) אחרי הבחירה.
